# Переносимый библиотечный шаблон

Контекст файла: `get_file_metadata` читает имя, thumbnail и страницы. `set_file_metadata({fileKey,thumbnailNodeId})` устанавливает thumbnail; необязательный `name` служит только точной проверкой уже установленного имени. Несовпадение — `FILE_RENAME_UNSUPPORTED` / `not_applied` до любых записей thumbnail. Plugin API [не позволяет менять figma.root.name](https://developers.figma.com/docs/plugins/api/DocumentNode/); переименование выполняется отдельно пользователем в Figma, затем подтверждается чтением. Совпадающее имя не записывается; при ошибке откатывается только принадлежащее операции изменение thumbnail.

`capture_library_template({fileKey,pageIds})` выполняет отдельное чтение исходных страниц. Сохраните `result.snapshot` локально. Снимок v2 содержит полное дерево со скрытыми ветками, реальные библиотечные ключи, source-relative пути и точные переопределения. Capture не импортирует и не меняет ресурсы исходника.

`assemble_library_template({fileKey,snapshot,mode:"apply"})` собирает сохранённый снимок в назначении с одной пустой страницей. Единственные внешние ресурсы сборки — опубликованные библиотечные компоненты, стили и Variables по сохранённым ключам. Исходный файл не открывается и не читается. Создаются PAGE/FRAME/SECTION и связанные INSTANCE; определения библиотек не изменяются. V1 не принимается: старые source-local style/variable IDs не переносимы.

`mode:"verify"` только читает marker и проверяет реальное дерево/ключи. Повторный apply возвращает `reused`, сохраняя заполненные Jira-тексты. Отсутствие marker — `TEMPLATE_NOT_MANAGED`; несовпадение marker или структуры — отдельная ошибка, не разрешение на пересборку. Status VARIANT может измениться только на заранее сохранённый вариант того же COMPONENT_SET и при сохранении дерева.

Снимок ограничен 20 страницами, 1000 узлами, глубиной 32 и 2 MB. Корневые контейнеры имеют закрытый список геометрических/Auto Layout/paint свойств; внутри экземпляров записываются только явные overrides. Поддержаны поля шаблона таски: width/height, visible/locked, characters, fontName/fontSize, fillStyleId/fills, hyperlink, styledTextSegments, textDecoration/textDecorationSkipInk. Mixed текст переносится диапазонами с точными шрифтами и ссылками; Variables и стили — опубликованными ключами, режимы — именами и anchor-переменной коллекции. Неподдержанные поля, изображения/video, внутренние NODE-ссылки, внешние mask/grid/reactions, отсутствующие опубликованные ресурсы останавливают операцию с конкретным кодом.

Успех: `{status,pages,rootIds,instanceKeys,verification,snapshotId}`. `pages` содержит `{sourceId,id,name}`; `rootIds` — `{sourceId,id,path}`; `instanceKeys` дополнительно содержит `libraryKey`. `snapshotId` — SHA-256 проверенного канонического содержимого. Для последующих правок используют целевые `id`, никогда исходные `sourceId`.

Read-back первой сборки проверяет дерево, библиотечные ключи, свойства, явные значения, диапазоны текста и режимы. Он не заменяет визуальную PNG-проверку Figma layout engine. Откат удаляет только созданные узлы/страницы и восстанавливает имя исходной пустой страницы; импортированные ресурсы могут остаться в кэше. При unknown/partial дождитесь idle и выполните verify/read-back; автоматически повторять apply нельзя.

Перед первой записью после импорта ресурсов повторно проверяются пустота назначения, исходная страница, имя и marker; перед записью marker проверяются полный список страниц и фактическое дерево без дополнительного await. Откат проверяет текущих потомков каждого созданного контейнера: если внутри появился чужой узел, контейнер сохраняется, операция возвращает `partial`, а `rollbackErrors` содержит его ID и ID чужих потомков. Ручное изменение имени исходной страницы или marker не перезаписывается. Оставшиеся контейнеры требуют чтения и адресной проверки перед ручной очисткой.

Прямые scalar-привязки внешних FRAME/SECTION (размеры, отступы, интервалы, радиусы, opacity/visible, strokeWeight) сохраняются как опубликованные ключи Variables и восстанавливаются после размеров. Paint-array aliases должны быть представлены в paints; произвольные массивы, неизвестные поля и другие неподдержанные shapes отклоняются как `UNSUPPORTED_TEMPLATE_BINDING`.

Обнаружение команд: `node scripts/call-tool.mjs list capture_library_template`. Вызов остаётся типизированным через `scripts/call-tool.mjs` с `--args` и `--output`; произвольный код/REST не нужен. Проверки без живой Figma: `node --test tests/library-template.test.mjs`, затем `npm test` (интеграционные тесты используют локальный loopback WebSocket).
