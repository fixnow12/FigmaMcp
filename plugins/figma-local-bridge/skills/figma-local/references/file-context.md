# Контекст файла

- `capture_library_template({fileKey,pageIds})` — отдельное чтение явно выбранных исходных страниц. Оно возвращает `snapshot` v2: полное дерево (включая скрытые ветки), source-relative пути, ключи опубликованных экземпляров/стилей/Variables, названия режимов, шрифты и точные переопределения. Сохрани JSON локально. Capture не изменяет источник. Пределы: 20 страниц, 1000 узлов, глубина 32, снимок до 2 MB.
- `assemble_library_template({fileKey,snapshot,mode:"apply"})` использует только локальный snapshot и опубликованные библиотеки. Исходный файл не читается; сборка в нём запрещена. Назначение должно содержать одну пустую страницу либо завершённую управляемую сборку того же снимка. Создаются простые PAGE/FRAME/SECTION и связанные библиотечные INSTANCE; определения компонентов не создаются и не изменяются. Стили и переменные импортируются по ключам, коллекции не пересоздаются. Неподдержанное свойство или дрейф дерева останавливают операцию.
- `mode:"verify"` только читает marker и фактическое дерево/ключи: `TEMPLATE_NOT_MANAGED` означает отсутствие marker, остальные ошибки управляемой сборки не разрешают fallback или пересборку. Повторный apply возвращает `reused`, сохраняя Jira-тексты. Только Status VARIANT допускает заранее сохранённый вариант из того же COMPONENT_SET; прочие связи проверяются точно. `rootIds` — записи `{sourceId,id,path}`, `instanceKeys` дополнительно содержат `libraryKey`; sourceId — идентичность источника, для записи используй только целевой id.
- При ошибке откатываются только созданные холстовые узлы/страницы и имя исходной пустой страницы. Импортированные ресурсы могут остаться в кэше. После unknown/partial дождись idle и выполни verify/read-back; не повторяй apply автоматически. Машинная verification не заменяет отдельную визуальную проверку PNG.
- Если новых команд нет в каталоге чата, проверь `scripts/call-tool.mjs list capture_library_template` и вызови типизированный инструмент того же Bridge через `--args` и `--output`. Не заменяй его произвольным JavaScript, REST или обращением к исходнику во время assemble.

- `activate_page({fileKey,pageId})` переключает только UI-контекст на страницу с точным PAGE ID. Перед следующей правкой убедись, что `get_status` возвращает тот же `currentPageId`.
- `get_file_metadata({fileKey})` читает `{name,thumbnailNodeId,pages}`. `pages` — полный упорядоченный список всех PAGE текущего документа в виде `[{id,name}]`, включая пустые страницы; имена возвращаются без нормализации.
- `set_file_metadata({fileKey,name?,thumbnailNodeId?})` задаёт thumbnail; `name` только проверяет уже установленное имя. `figma.root.name` доступно Plugin API только для чтения: несовпадающий `name` возвращает `FILE_RENAME_UNSUPPORTED` / `not_applied` до записи thumbnail. Совпадающее имя не вызывает setter. Для переименования требуется отдельное действие пользователя в Figma; не обещай переименование через Bridge и не повторяй неподдержанную запись. Передай хотя бы одно из полей; thumbnail должен ссылаться на FRAME, COMPONENT, COMPONENT_SET или SECTION текущего файла. Откат восстанавливает только собственное изменение thumbnail и сохраняет чужие изменения имени.
- Эти команды не меняют содержимое компонентов, Variables или библиотек.
