# Design spec

## Точность оформления

`fills` и `strokes` принимают типизированные массивы Figma Paint: SOLID,
четыре вида градиента и IMAGE. Сохраняются float RGB, opacity, visible,
blendMode и цветовые boundVariables. IMAGE сохраняет imageHash, scaleMode,
imageTransform, scalingFactor, rotation и filters. Hash должен существовать
в целевом файле; иначе пакет отклоняется до записи. Экспорт исходных байтов
выполняет `export_assets`, а импорт байтов — узел `type: "image"`.

Приоритет: `background`/`fill`/`color` → `fillStyleId` → `fills` →
`textRuns[].fills`; для обводок `stroke` → `strokeStyleId` → `strokes`.
Пустой массив удаляет заливки/обводки. Новые вложенные frame/component без
явного оформления прозрачны; корневой экран сохраняет стандартный фон Figma.

Поддержаны `topLeftRadius`, `topRightRadius`, `bottomLeftRadius`,
`bottomRightRadius`, `cornerSmoothing`, `strokeAlign`, четыре отдельных
`stroke*Weight`, `dashPattern`, `blendMode`, `rotation`, `constraints`,
`minWidth/maxWidth/minHeight/maxHeight`. Отдельные радиусы применяются после
общего `cornerRadius`. Применение к неподходящему типу узла отклоняется.
`x/y` используются только в свободной раскладке или с
`layoutPositioning: "ABSOLUTE"`; обычный Auto Layout продолжает управлять
положением. В layout поддержаны отрицательный gap, counterAxisSpacing,
strokesIncludedInLayout и itemReverseZIndex.

Текст поддерживает `textAutoResize`, `textAlignVertical`, `paragraphSpacing`
и `paragraphIndent`; последние два — также внутри textRuns. Ширина Fill
при создании текста не включает автоматически расширение по содержимому.

SVG масштабируется через `rescale`, чтобы менялись сами векторы внутри,
а не только границы контейнера. Ширина и высота должны сохранять пропорции.

`inspect_selection.coverage` сообщает полноту обхода и узлы для дочитывания.
Это полнота дерева, а не гарантия поддержки всех свойств. `fidelityWarnings`
указывает известные ограничения. Grid, произвольные affine-трансформации,
маски как связи между слоями, видео, прототипные переходы и анимации пока
не воссоздаются этой спецификацией. Связи экземпляров нужно создавать через
`use_component`, переменные — через `bind_variables`. У SVG не обещается
сохранение связей с Variables, компонентами и исходной иерархии векторов.

`render_screen` принимает плоскую типизированную спецификацию экрана. Актуальная JSON Schema находится в `../../../schemas/design-spec.schema.json` относительно этого файла.

Основные правила:

- у экрана и каждого узла должен быть постоянный уникальный `key`;
- дочерний узел ссылается на родителя через `parentKey`;
- поддержаны `frame`, `component`, `componentSet`, `text`, `rectangle`, `ellipse`, `image` и `svg`;
- ссылки на токены записываются как `$colors.primary` и `$numbers.gap`;
- повторный `render_screen` с тем же ключом удаляет предыдущий экран только после успешной сборки нового; посторонние элементы старой секции сохраняются;
- после первого создания последующие небольшие изменения выполняются через `patch_nodes`.

## Точечные изменения

`patch_nodes.patches[].set` поддерживает `fontFamily`, `fontWeight` (название начертания Figma), `fontSize`, `lineHeight` в пикселях, `letterSpacing`, `textAlign`, `clipContent` и `layout` с направлением, выравниванием и переносом. Непереданные свойства `layout` сохраняются. `padding` числом задаёт все стороны; в объекте непереданные стороны получают 0.

Для `append` используй конкретные значения: у этой операции нет словаря токенов. Ключи добавляемых узлов должны быть уникальны во всём пакете и на странице. Родитель внутри `append` задаётся `parentKey`; циклы и вложение в текст или фигуры отклоняются до записи.

Перед применением пакет проверяет все найденные цели, поддерживаемые свойства и необходимые шрифты. Если ошибка возникла при записи, операция пытается восстановить изменённые свойства и удалить все созданные ею узлы. Это не транзакция Figma: итог отката указан в `operationStatus`, а тайм-аут или отключение требуют повторного чтения. При `ignoreMissing: true` пропущенные цели возвращаются в `missing` и не попадают в `appended`.

`use_component` принимает `sourceId` для обычных локальных компонентов без служебного `key`, включая источник на другой странице. Родитель экземпляра должен находиться на текущей странице.

Токены JSON-спеки разворачиваются в значения; это не привязки Figma Variables. Для настоящих привязок к существующим переменным используй `bind_variables`; правила описаны в [design-operations.md](design-operations.md).

## Типографика и эффекты

`inspect_selection` возвращает фактические `fontFamily`, `fontStyle`, `fontSize`,
`lineHeight`, `letterSpacing`, `textCase`, `textDecoration`, `textStyleId`,
`effects` и `effectStyleId`. При воссоздании используй эти значения: не подбирай
размер и начертание по PNG, если свойства можно прочитать. `fills` и `strokes`
возвращаются как исходные paints Figma, включая привязки к переменным.

Эти параметры типографики доступны в `render_screen`, `patch_nodes.set` и
`patch_nodes.append`. `fontStyle` — точное название начертания Figma, например
`Medium`, `Semi Bold` или `Italic`. Старое поле `fontWeight` остаётся совместимым
алиасом; если указаны оба поля, приоритет у `fontStyle`. При недоступном шрифте
операция завершается с ошибкой. Автоматической замены на `Regular` нет; допустимо
только однозначное совпадение того же начертания по написанию (`SemiBold` →
`Semi Bold`) в том же семействе.

`lineHeight` принимает число в пикселях, `"AUTO"`, `{ "unit": "AUTO" }` или
`{ "unit": "PERCENT", "value": 120 }` / `{ "unit": "PIXELS", "value": 24 }`.
`letterSpacing` принимает число в пикселях или объект с `PIXELS` / `PERCENT`.
Для смешанного оформления чтение возвращает `mixedTextProperties` и `textRuns`
с диапазонами `[start, end)` в кодовых единицах UTF-16 и свойствами каждого
участка. Их можно передать при создании или правке. Диапазоны должны идти по
порядку, не пересекаться и помещаться в текст. Замена `content` смешанного текста
требует явных `textRuns` для нового содержания. Цвета участков читаются в
`textRuns[].fills` и обратно совместимом `textRunFills`; для записи используй `textRuns[].fills`.

`textStyleId` и `effectStyleId` позволяют назначить существующий доступный стиль
в этом файле через асинхронный API. Стиль применяется первым; явно переданные
свойства затем переопределяют его значения. Чтобы сохранить связь со стилем без
переопределений, передавай только ID. Это не изменяет определение самого стиля.

`effects` поддерживает массив внешних и внутренних теней (`DROP_SHADOW`,
`INNER_SHADOW`), а также обычное размытие (`LAYER_BLUR`, `BACKGROUND_BLUR`).
Массив доступен у экрана и его узлов, включая `patch_nodes.set` и `append`.
Пустой массив удаляет эффекты; отсутствие поля сохраняет текущие эффекты.
Вложенные контейнеры создаются с `clipContent: false` по умолчанию, чтобы не
обрезать тени дочерних карточек. Явный `clipContent` поддерживается при создании
контейнера и в `patch_nodes.set`; чтение тоже возвращает это свойство. Для
карточек со spread учитывай исходное `clipContent`: Figma ограничивает применение
spread у фреймов с отключённым обрезанием содержимого.
Цвет тени — `#RRGGBB`, `#RRGGBBAA` или точный объект RGBA из чтения Figma.
Сохраняй порядок теней, прозрачность, смещение, радиус, spread, blendMode и
`boundVariables` (привязки эффектов к переменным).
Прочие типы эффектов и дополнительные поля, возвращённые Figma (например,
прогрессивное размытие), не следует молча отбрасывать:
используй доступный `effectStyleId` либо обозначь ограничение.

```json
{
  "key": "payment-card",
  "set": {
    "effects": [
      {
        "type": "DROP_SHADOW",
        "color": "#0807251A",
        "offset": { "x": 0, "y": 2 },
        "radius": 8,
        "spread": 0,
        "blendMode": "NORMAL",
        "visible": true
      }
    ]
  }
}
```
