# Сборка экрана по исходнику

Запрос пользователя: «Собери похожий экран, переименуй заголовок и замени список на новую кнопку». Пользователю не нужны названия команд или JSON. Агент определяет ID экрана, заголовка и списка через `inspect_selection`, затем вызывает `recreate_screen`:

```json
{
  "fileKey": "ключ выбранного файла",
  "sourceId": "ID экрана",
  "name": "Новый экран",
  "changes": [
    {"sourceId": "ID заголовка", "action": "update", "set": {"content": "Поддержать фонд"}},
    {"sourceId": "ID списка", "action": "replace", "nodes": [
      {"key": "continue", "type": "frame", "name": "Продолжить", "width": "fill", "height": 48, "background": "#7030F5", "cornerRadius": 12,
       "layout": {"direction": "horizontal", "primaryAlign": "center", "counterAlign": "center", "padding": 12}},
      {"key": "label", "parentKey": "continue", "type": "text", "name": "Надпись", "content": "Продолжить", "fontFamily": "Factor IO", "fontStyle": "Medium", "fontSize": 16, "color": "#FFFFFF"}
    ]}
  ]
}
```

ID и шрифты в примере — заполнители: используй фактические значения из файла. Замена наследует положение и размеры удаляемого блока, если новые значения не заданы. `update.layout` дополняет исходную раскладку; остальные переданные свойства заменяют соответствующее значение целиком. Смешанный текст требует явных диапазонов `textRuns`. Новые ключи автоматически получают уникальный префикс сборки.

`dryRun: true` проверяет итоговую структуру и шрифты, не создавая слоёв. Без changes выполняется сравнение геометрии с источником; с changes проверяются тексты и шрифты сохранённых слоёв. Новые элементы и поведение раскладки проверяй по итоговому PNG. Ответ `applied` сохраняется даже при ошибке снимка; дорабатывай созданный фрейм, не запускай повторную реконструкцию.

Предварительная проверка учитывает итоговую сборку: для явно заданных `remove` и `replace` ресурсы исключаемой ветки не экспортируются и её шрифты не загружаются. Исходное дерево по-прежнему должно быть прочитано полностью. Это не разрешение автоматически удалять проблемные слои — изменения должны соответствовать запросу пользователя.

При неподдержанных свойствах ответ содержит `code: "RECONSTRUCTION_BLOCKED"`, `operationStatus: "not_applied"`, список `blockers` с ID, именами и причинами, а также `nextStep`. Покажи все причины из списка; повтор того же вызова не исправляет исходник. Неполное чтение и ошибка загрузки ресурсов тоже останавливают работу до записи.

Настройки размеров и отражения применяются внутри общей операции создания: при ошибке новая сборка откатывается. Сравнение и снимок выполняются после записи; их сбой не повод повторять создание. Если связь пропала после отправки записи, статус `unknown` сохраняется до проверки результата на холсте.
