# Figma Local

Используй только инструменты MCP-сервера `figma-local`: `get_status`, `inspect_selection`, `export_assets`, `patch_nodes`, `render_screen`, `recreate_screen`, `use_component`, `clone_nodes`, `move_nodes`, `find_assets` `bind_variables`, `set_text_links` и `set_reactions`.

## Рабочий процесс

1. Для незнакомого макета сначала вызови `inspect_selection`.
2. Известный узел читай через `nodeId`, несколько узлов — через `nodeIds`. Узел по имени ищи через `find_assets` с `kind: "nodes"`; при неоднозначности уточни цель. Если нет ни ID, ни описания цели, попроси выделить нужный узел в Figma Desktop.
3. Для точечной правки используй `patch_nodes` и стабильные `key` или ID из чтения; не пересоздавай весь экран. Ключ спецификации передавай как `{key:"screen-title",set:{…}}`, Figma ID — как `{id:"16:85",set:{…}}`: эти поля не взаимозаменяемы. Для сравнения оформления читай `detail: "full"`: он возвращает типографику, стили, привязки переменных и настройки размеров.
4. Для варианта существующего экрана (добавить промо, ошибку, состояние, изменить блок) используй `recreate_screen` с `sourceId` и `changes`, даже если пользователь говорит «нарисуй варианты», а не «воссоздай». Для копии без изменения внутренней структуры — `clone_nodes`, для переноса — `move_nodes`. `render_screen` используй для дизайна с нуля, когда нет исходного экрана или пользователь запросил новую композицию. Все узлы должны иметь уникальные стабильные `key`.
5. Экземпляры компонентов создавай через `use_component`: локальный источник задаётся `sourceId` или `sourceKey`, библиотечный — `libraryKey`; родитель — `parentId` или `parentKey`.
6. После записи проверь PNG из ответа инструмента или повтори `inspect_selection` с `screenshot: true`. Для варианта сравни его с исходником при одинаковом масштабе: ширина экрана, оболочка, навигация, иконки, неизменённые блоки и типографика должны сохраняться. Успешная запись, Auto Layout и отсутствие выходов за границы не доказывают сходство или правильность сценария.

Для первой новой спецификации используй `render_screen` с `dryRun:true`: он проверяет свойства, координаты и загрузку шрифтов без создания слоёв. Это не проверка итогового SVG, кликов или визуального совпадения. Координаты `x/y` требуют у родителя `layout.direction:"none"` либо у дочернего слоя `layoutPositioning:"ABSOLUTE"`. При `FONT_SERVICE_TIMEOUT` проверяй доступность указанного шрифта; активация целевой вкладки — диагностический шаг, если она действительно была фоновой. Не проси открыть уже открытую вкладку. После восстановления повтори только dryRun. Если ошибка сохраняется, проверяй доступность шрифта. Наличие WebSocket и ответ Plugin API не гарантируют загрузку шрифтов в фоновом файле; `isActive` сам по себе не доказывает причину. Тайм-аут не доказывает отсутствие шрифта и не разрешает его подмену.

ID узла принадлежит конкретному файлу: всегда сохраняй пару `(fileKey,nodeId)`. `sourceId` в `clone_nodes`/`recreate_screen` должен принадлежать переданному `fileKey`; команды не переносят узлы между файлами. Для нового результата в другом файле прочитай источник с его `fileKey`, затем используй новую спецификацию `render_screen` в файле назначения. Ошибка сети при чтении чужого ID не доказывает новую возможность или её отсутствие — сначала исправь адресацию.

При работе от исходника сохраняй его шаги и платформенные размеры; не заменяй телефон произвольной широкой карточкой и не удаляй оболочку ради новой секции. Новый блок оформляй по ближайшему аналогу в исходнике. Если запрошены web/app, а доступен только app, найди web-исходник через `find_assets`; при его отсутствии обозначь web как новую концепцию, не как точную адаптацию. Числа лимитов и даты используй из подтверждённых условий либо явно помечай как пример; дневной и месячный лимиты не взаимозаменяемы. URL в подписи макета не означает, что прототипный переход настроен.

## Глубина чтения

- В `inspect_selection` передавай целые числа: `depth` от 0 до 8 (по умолчанию 3), `maxNodes` от 1 до 1000 (по умолчанию 200). `depth` считается от каждого запрошенного узла; 0 возвращает сам узел без детей. Для `nodeIds` допустимо от 1 до 50 ID; не передавай одновременно `nodeId` и `nodeIds`.
- Для более глубокого дерева читай ветки отдельными вызовами: при `coverage.complete: false` бери `nodeId` из `coverage.unread` и вызывай `inspect_selection` с этим ID, тем же `fileKey`, `detail: "full"` и `depth: 8`. Повторяй для оставшихся непрочитанных веток. Не увеличивай `depth` выше 8 или `maxNodes` выше 1000.
- Если чтение отклонено с `Input validation error` (может отображаться как `MCP error -32602`), исправь указанное в сообщении поле перед повтором. Например, для `Number must be less than or equal to 8 at depth` уменьши `depth` до 8 и дочитай ветки отдельно; повтор того же запроса не поможет.
- Для обзора большой страницы начни с `depth:1` и `maxNodes:100`, затем читай нужные ветки по ID. Если ответ обрезан клиентом, обрабатывай сохранённый JSON локально; увеличение глубины увеличивает ответ. При `FIGMA_READ_TIMEOUT` отсутствие узла или библиотеки не подтверждено. Ошибка содержит `blockers` с зависшим ресурсом; проверь статус этого `fileKey`, затем выбери меньшую ветку или другой подтверждённый источник. Составные ID экземпляров возвращай целиком, как в чтении.

## Точное воссоздание

- Для «воссоздай / перерисуй исходный экран в отдельном фрейме, без копирования» используй `recreate_screen` с `sourceId` и явным `fileKey`. Инструмент полностью читает исходное дерево и создаёт новые узлы без `clone()`, сохраняя фактические свойства. Не переписывай исходный экран вручную в `render_screen`, если его может воссоздать эта команда. `render_screen` предназначен для нового дизайна по описанию.
- Для «собери почти такой же экран, но с другими элементами» передай `changes` в `recreate_screen`. Пользователь описывает результат обычными словами; выбор команд и подготовка параметров — работа агента. Сначала прочитай композицию и нужные цели, затем передавай только изменения по их исходным ID. Глубокое чтение всего экрана, ресурсы и сборка выполняются внутри плагина.
- В `changes` каждая операция содержит `sourceId` и `action`: `update` с `set` меняет свойства; `remove` исключает ветку; `replace` с `nodes` заменяет блок; `append` с `nodes` добавляет детей во фрейм. У новых узлов уникальные `key`, `parentKey` ссылается только внутрь этого списка, корни списка без `parentKey`. Новые блоки описывай со шрифтами и Auto Layout. Все изменения проверяются до записи; исходный экран не патчится. Подробный пример — [references/reconstruction.md](references/reconstruction.md).
- `recreate_screen` с `dryRun: true` проверяет готовность без создания. Недоступный шрифт, неполное чтение, видеозаливки, Grid, skew и отражённые контейнеры блокируют сборку: сообщи причину, не обходи её заменами. Пределы — 2000 узлов и глубина 64; при превышении работай с меньшими блоками.
- Воссоздаётся видимое состояние: скрытые ветки исключаются и учитываются в `skippedHidden`. Экземпляры и группы воссоздаются обычными фреймами; значения Variables фиксируются, связь с библиотекой не переносится. Отражённые VECTOR с исходными контурами сохраняют матрицу отражения. Поворот групп пересчитывается в локальные координаты новых фреймов. Маски сохраняют `isMask`, `maskType` и порядок соседей. Линии создаются как LINE, векторы — как VECTOR по исходным контурам; геометрические маски без vectorPaths — по fillGeometry, остальные фигуры — через SVG. Не экспортируй маску отдельно: Figma может вернуть пустой результат. Для сохранения связей экземпляров используй `use_component`, а не называй эту реконструкцию сохранением библиотеки.
- После `recreate_screen` проверь `result.verification` и PNG. `checked` означает только проверенные геометрию, текст и шрифт, не пиксельное совпадение. Для правок используй `result.mapping` и `patch_nodes`, не запускай повторную сборку. Ошибка PNG или проверки после `operationStatus: "applied"` не отменяет созданный экран.
- При `changes` геометрия намеренно отличается; `verification.scope` ограничен текстами и шрифтами сохранённых узлов. Новые блоки, переносы строк и Auto Layout проверь по PNG и повторному чтению результата.
- Сначала прочитай `detail: "full"` и просмотри PNG исходника. `coverage.complete: false`, `truncated: true` или `childCount > 0` без `children` означает неполное чтение. Дочитай каждую ветку из `coverage.unread` по `nodeId`; не придумывай недостающие тексты и способы оплаты. У старых версий `truncated: false` не учитывал ограничение глубины.
- Сверь весь видимый текст, включая верхнюю строку подвала, телефон, язык и юридические ссылки. `effectiveVisible` учитывает скрытых родителей: текст скрытого меню не относится к видимому экрану.
- Для иконок и логотипов используй `export_assets` с `format: "svg"` на отдельном значке или его контейнере, затем создавай `type: "svg"`. Не заменяй их кружками, буквами или Unicode-стрелками. Не экспортируй весь экран единым SVG/PNG вместо редактируемой структуры.
- IMAGE-заливку в том же файле передавай через `fills` с исходными `imageHash`, `imageTransform`, `scaleMode` и `filters`. `export_assets` с `format: "images"` возвращает исходные байты. Hash другого файла не переносим; для него нужны байты и новый image. Проверяй `complete` и `warnings` экспорта.
- Передавай точные `fills`/`strokes`, включая прозрачность каждой заливки; не округляй RGB до hex и не умножай alpha повторно на opacity слоя. Для смешанного текста передавай `textRuns[].fills` вместе с типографикой.
- Сохраняй радиус экрана, радиусы отдельных углов, `cornerSmoothing`, обрезание, порядок всех теней и обводок, Fill/Hug/Fixed и настройки Auto Layout. Не меняй семейство или вес шрифта по изображению, если доступны фактические значения.
- `fidelityWarnings` обозначает известные ограничения (Grid, отражения/skew). Отдельные сложные значки допустимо воссоздать через SVG; не объявляй полное совпадение для неподдержанного свойства.
- После сборки сравни PNG исходника и результата в одном масштабе, затем проверь тексты, число видимых иконок, размеры, радиусы и paints. Наличие PNG само по себе не доказывает совпадение. Используй `patch_nodes` для доводки.

## Дизайн-система и готовые блоки

- Через `find_assets` ищи компоненты (`kind: "components"`), локальные стили (`styles`) и переменные (`variables`). Поиск по страницам по умолчанию ограничен текущей; `scope: "file"` загружает страницы файла без переключения активной. Учитывай `hasMore` и `nextOffset`.
- `library_collections` и `library_variables` возвращают метаданные доступных библиотечных Variables. Поиск не импортирует их и не представляет полный каталог внешних компонентов или стилей.
- Пустой `library_collections` не доказывает недоступность компонентов или всех привязок Variables. Доступность экземпляра проверяется отдельно по известному `libraryKey` через `use_component` в разрешённом назначении; доступность уже существующей переменной — по её ID. До такой проверки сохраняй соответствующую возможность как неизвестную.
- Через `bind_variables` привязывай уже доступные в файле переменные по `variableId`; `null` снимает привязку. Сами переменные и их значения эта операция не редактирует.
- Не передавай `allowComponentChanges: true`, пока пользователь не подтвердил изменение оригинала компонента после предупреждения о влиянии на библиотеку. Обычные экземпляры и рабочие фреймы не требуют этого флага. Создание экземпляра предпочтительно копированию определения компонента.
- Правила индексов, границы структурных операций и примеры параметров описаны в [references/design-operations.md](references/design-operations.md). Прочитай этот файл перед клонированием, переносом или привязкой переменных.

## Ссылки и прототипы

- `set_text_links` добавляет/удаляет настоящие ссылки на весь TEXT или диапазоны `[start,end)` в индексах UTF-16. `target` — `{type:"URL",value:"https://…"}` или `{type:"NODE",value:"id"}`; `null` снимает ссылку. Диапазоны одного узла не пересекаются. Цель NODE может быть на другой странице файла, но не внутри экземпляра.
- `set_reactions` настраивает переходы на слоях текущей страницы. По умолчанию `mode:"upsert"` заменяет только переданные типы триггеров, сохраняя остальные. `mode:"replace"` заменяет весь список, `reactions:[]` с этим режимом удаляет все реакции узла. Перед полной заменой прочитай существующие реакции и убедись, что задача требует их удаления.
- Поддержаны ON_CLICK/ON_HOVER/ON_PRESS/ON_DRAG и одно действие на триггер: NODE с NAVIGATE/OVERLAY/SCROLL_TO, URL, BACK, CLOSE. NAVIGATE/OVERLAY ведут в другой верхнеуровневый FRAME на той же странице (в том числе внутри SECTION); SCROLL_TO — к вложенному блоку того же экрана. Для другой страницы используй URL или текстовую NODE-ссылку, не подставляй её ID в NAVIGATE. Figma Slides и FigJam не входят в этот контракт.
- Обе команды поддерживают `dryRun:true`, проверяют пакет перед записью и возвращают фактически прочитанные связи. После записи повтори `inspect_selection`: `hyperlinks` содержит связанные диапазоны, `reactions` — текущие реакции. Эти поля читаются и в compact, и в full. `actualClicks:"not-tested"` означает, что клики в Present ещё не проверены; PNG тоже не доказывает кликабельность.
- `recreate_screen` пока переносит только видимое состояние, не связи. Ссылки и переходы на новых узлах задавай отдельным вызовом по полученным ID. Примеры, анимация и ограничения — [references/interactions.md](references/interactions.md).

## Подключение

- Не открывай Figma в браузере, не используй Playwright, REST API, официальный удалённый Figma MCP, API-токены, `list_mcp_resources` или `list_mcp_resource_templates` для операций с холстом.
- Ссылка на Figma нужна только для извлечения `fileKey`; открывать ссылку не требуется.
- Если файл известен, начинай с `get_status({fileKey})`. Общий `connected:true` относится к любому файлу; проверяй `target.connected`. Отсутствие цели в старом общем списке не доказывает, что её плагин закрыт. До просьбы открыть уже открытый файл выполни одно адресное `inspect_selection` с `fileKey` и известным `nodeId` (из URL `0-1` преобразуется в `0:1`). Если чтение успешно — продолжай. Если цель всё ещё недоступна и пользователь сообщает о зелёном Bridge, диагностируй рассогласование регистрации, не повторяй просьбу запустить плагин и не объявляй фоновые вкладки причиной без проверки. Только при подтверждённом отсутствии запущенного Bridge проси запустить **Plugins → Development → Figma Desktop Bridge**.
- Для старта используй один `get_status` с известным `fileKey`: он возвращает файлы и диагностику без чтения холста. При `diagnostics.ready: true` сразу переходи к задаче; не запускай дополнительно `ps`, установщик, полный `verify` или тестовый PNG ради подключения. PNG нужен для самой задачи и проверки результата. Pairing-код предназначен только для локального ввода в Bridge, не включай его в отчёты и коммиты.
- При проблеме следуй `diagnostics.state`, `nextAction` и `issues`. `current.mcp`, `current.broker`, `current.plugin` сравнивают нужные версии; у broker отдельная `expectedBrokerRevision`. `get_status.execution` дополнительно проверяет ответ Plugin API и занятость конкретного файла: `responsive`, `busy`, `activeOperation` с именем, длительностью и признаком записи. `ready` учитывает эту проверку на момент ответа; внутри каждой команды она повторяется. Статус одного файла не доказывает готовность другого.
- После обычного обрыва следующий вызов сам создаёт новое защищённое соединение. `get_status` также автоматически обновляет устаревший broker при изменении его исходников в том же каталоге, когда нет активных/ожидающих операций и неизвестных результатов. Если Codex установил новую сборку в другой каталог кэша, старый broker не видит это изменение: нужен разовый перезапуск по инструкции README после завершения операций. При `maintenance.state: "deferred"` дождись операций; для `uncertainFiles` сначала выполни проверочное чтение. Отправленные записи не повторяются.
- `MCP_OUTDATED` требует одного переподключения MCP в клиенте; каталог новых инструментов может потребовать нового чата. `PLUGIN_OUTDATED` требует обновить персональную сборку при необходимости и переоткрыть Bridge. Старый broker без поддержки автоматического обновления требует однократного перезапуска broker и MCP после проверки операций. Не убивай процессы по имени и не перезапускай исправный broker ради нового каталога команд.
- Прочитай `diagnostics.warnings` в `get_status`: там различаются устаревшие MCP, broker и сборка плагина. `isActive` — последнее событие файла (подключение, выделение или смена страницы), а не достоверно активная вкладка Figma. `connected: true` подтверждает WebSocket, но не готовность Plugin API; не объявляй неактивную вкладку причиной ошибки только по этому флагу.
- Если подключено несколько файлов, `inspect_selection` без `fileKey` возвращает `connectedFiles`, `requiresFileKey: true` и `selectionInspected: false` без ошибки и без чтения холста. Выбери файл по ссылке или названию из запроса пользователя, затем передавай его `fileKey` во всех операциях. Список также доступен через `get_status`. Если цель не указана, уточни файл у пользователя; не перебирай выделения в разных файлах, поскольку они могут сохраняться в нескольких вкладках. Изменения без явного `fileKey` в этом случае отклоняются.
- Не предлагай произвольный JavaScript: сервер принимает только типизированные операции.
- Если в каталоге текущей задачи нет нового инструмента, это не означает, что Figma Bridge нужно перезапустить. Проверь каталог установленного MCP через `node <корень-плагина>/scripts/call-tool.mjs list`. Этот клиент вызывает только типизированные инструменты того же `figma-local`; он не обращается к холсту напрямую. Если нужная команда опубликована, выполни её через этот клиент с `--args <JSON-файл>` и `--output <каталог результата>`, затем прочитай `result.json` и PNG. Параметры готовит агент. Для проверки устаревшей установки — `scripts/verify-codex-install.mjs`; переустановка нужна только при несовпадении копии с исходниками. Не повторяй изменяющий вызов после тайм-аута.
- Если отсутствуют поля `detail` или `nodeIds`, проверь именно схему: `node <корень-плагина>/scripts/call-tool.mjs list inspect_selection`. Не передавай неизвестные клиенту поля повторно и не объединяй несколько ID в одну строку `nodeId`. Для проверки команды и схем из `opencode.json` запусти `node <корень-плагина>/scripts/verify-install.mjs --opencode`. Эта проверка запускает новый MCP-процесс; она не обновляет каталог уже открытого чата. Для его обновления переподключи `figma-local` в OpenCode и открой новый чат.

## Результат и ошибки

- `operationStatus: "applied"` означает, что изменения выполнены. При `screenshot.status: "failed"` не повторяй запись: получи снимок отдельным `inspect_selection` по ID из результата.
- `not_applied` — предварительная проверка отклонила пакет; `rolled_back` — изменения пакета отменены; `partial` — восстановление неполное, проверь указанные узлы и `rollbackErrors`.
- После `partial` прочитай затронутые узлы до следующей записи. Если требуемое значение уже сохранено, повторять его не нужно. Одинаковая ошибка на каждом узле пакета требует диагностики Bridge, а не серии одиночных записей с объявлением этих ошибок штатным успехом.
- `unknown` после тайм-аута или обрыва связи не доказывает, что изменений не было. Не повторяй изменяющую команду автоматически; сначала дождись восстановления соединения и прочитай затронутые узлы. Тайм-аут не может прервать уже выполняющийся вызов Plugin API.
- При `PLUGIN_UNRESPONSIVE` новая команда не отправлена: попроси открыть целевую вкладку Figma и проверить окно Bridge. При `PLUGIN_BUSY` / `FILE_BUSY` предыдущая команда ещё выполняется. Следуй `nextStep`; не устраивай циклы `sleep 20/60/90` с одинаковыми запросами. После тайм-аута предыдущей записи её результат по-прежнему неизвестен, даже если следующая команда имеет `not_applied`.
- Замена содержания текста со смешанным оформлением требует явных `textRuns` для нового текста; не заменяй смешанные шрифты/цвета одним значением без запроса пользователя.

Формат экрана, токены и правила стабильных ключей описаны в [references/design-spec.md](references/design-spec.md). Для `render_screen` используй плоский `spec.nodes` и `parentKey`; каждый новый или изменённый пакет сохрани и проверь через `scripts/validate-spec.mjs` из корня плагина перед dryRun. Отправляй проверенный JSON без ручной пересборки. Успех dryRun относится только к переданному пакету: шрифты последующих слайдов и полное чтение результата он не подтверждает.
