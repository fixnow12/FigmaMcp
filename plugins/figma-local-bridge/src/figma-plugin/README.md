# Исходники Figma Desktop Bridge

Локальный development-плагин версии **0.3.0**. После установки подключается к
доверенному локальному broker автоматически, без ввода кода.

## Установка

1. Запустите `scripts/install.sh` или `scripts/install.ps1` из корня репозитория.
2. В Figma Desktop выберите **Plugins → Development → Import plugin from manifest…**.
3. Укажите персональный manifest, путь к которому напечатал установщик:
   `~/.figma-local-bridge/figma-plugin/manifest.json` на macOS или
   `%USERPROFILE%\.figma-local-bridge\figma-plugin\manifest.json` на Windows.
4. В нужном файле запустите **Figma Desktop Bridge — Auto** и оставьте окно открытым.
5. Попросите AI прочитать выделение. Bridge подключится автоматически.

`manifest.template.json` — внутренний шаблон сборки, он не содержит ключей установки.
Для импорта используйте только `manifest.json` через ярлык «Плагин Figma» в корне
проекта или по персональному пути выше. При обновлении выполните установщик снова
и перезапустите Bridge и AI-приложение. Путь, ID плагина и ключи сохранятся;
повторный импорт при неизменном пути не требуется.

## Подключение и безопасность

Один broker слушает `127.0.0.1:9233`. И Figma, и MCP проверяют его закреплённый
публичный ключ; broker проверяет разные ключи Figma и MCP. Команды, ответы и
метаданные передаются через шифрованный канал с защитой от подмены и повторов.
До взаимной проверки доступ к данным файла и выполнение команд заблокированы.

Файл доступен доверенным MCP-сессиям без постоянного закрепления за чатом.
Команды к одному файлу выполняются по очереди. Если файлов несколько, AI должен
указать fileKey. Кнопка **Отключить** закрывает связь; **Подключить**
возобновляет поиск. Закрытие окна прекращает доступ к этому файлу.

## Статусы операций

Под строкой подключения показаны текущий файл и страница, выполняемая или последняя операция. MCP передаёт название команды явно; код операции не используется для распознавания действия. Старый MCP без метаданных отображается как «Операция Figma».

Журнал различает ожидание в очереди плагина, выполнение, успех, отказ до записи, полный и неполный откат, неизвестный результат. После тайм-аута проверьте макет перед повтором. Поздний ответ не превращает неизвестный результат в подтверждённый успех. Очередь показывает только команды, уже полученные плагином, а не ожидание внутри MCP-сервера.

Экспорт PNG отображается отдельно от изменения макета. Каждая операция имеет свою строку и длительность (включая ожидание); одновременные одинаковые команды не объединяются. Экспорт журнала содержит результат, контекст и длительность, но не код команд и не pairing-код. Видны последние 50 записей, в памяти для экспорта сохраняются последние 500. После перезапуска окна история сбрасывается; восстановления результатов по ID пока нет.

Обновляйте обе части: MCP и development-плагин через повторный запуск установщика и импорт персонального manifest. Новые названия требуют обновлённого MCP, а события очереди — обновлённого `code.js`.

При локальной переустановке версия Codex-пакета может содержать суффикс `+codex.<метка>`, который заставляет Codex обновить кеш. Базовая версия до `+` совпадает с версиями MCP и Figma Bridge; суффикс не является новой версией протокола. Обновлённый пакет подхватывается в новой задаче Codex.

Ключи и персональная сборка защищены файловыми правами ОС, но не зашифрованы на
диске. Не пересылайте этот каталог. Полный доступ к вашей учётной записи ОС
находится вне границы защиты. Подробности, ограничения и отзыв ключей:
[инструкция проекта](../../../../README.md).
