# Автоподключение 0.3.0

Пользователь один раз запускает установщик и импортирует персональный manifest.
Открытие Bridge — Auto в файле разрешает подключение доверенной установки без
кода и диалогов. Отключить закрывает канал; Подключить возобновляет поиск.

## Установка и хранение

`scripts/prepare-install.mjs` генерирует три независимых Ed25519 seed: broker,
Figma UI и MCP-клиент. Повторная установка сохраняет ключи. Персональные файлы
пишутся атомарно в `~/.figma-local-bridge`, вне репозитория и кэша Codex.
`FIGMA_LOCAL_STATE_DIR` позволяет задать отдельный каталог для тестов.
ID Figma-плагина сохраняется: существующие служебные pluginData-ключи узлов
остаются доступны после обновления. Уникальность установки задаётся ключами.

На macOS каталог имеет права 0700, файлы 0600; владелец и отсутствие симлинков
проверяются до чтения. На Windows задаётся ACL только владельца и SYSTEM;
при загрузке проверяется владелец и отсутствие разрешений другим субъектам.
Это защита файлов правами ОС, а не Keychain/DPAPI или шифрование на диске.

UI содержит только собственный seed и публичный ключ broker. Серверный и
MCP seed в UI не включаются. `figma.clientStorage`, макет Figma, HTTP health,
конфигурация проекта и логи не используются для передачи секретов.
Публиковать персональную сборку нельзя. На другой машине нужна новая установка.

## Соединение

MCP остаётся stdio-процессом с четырьмя типизированными инструментами. При первом
вызове он подключается к broker или запускает его. Единственный broker слушает
127.0.0.1:9233. Захват порта ОС служит атомарным выбором одного процесса, поэтому
параллельный старт нескольких MCP не создаёт несколько активных broker.
Порт 9233 отделён от старого диапазона ручного сопряжения 9223–9232.
Если порт занят чужим сервером, проверка ключа не проходит; обхода проверки нет.

Оба клиента (UI и MCP) используют общий протокол `figma-local-secure-v2`:

1. Broker отправляет версию протокола, порт, публичный ключ, случайный nonce и
   эфемерный X25519 key; всё подписано его Ed25519 ключом.
2. Клиент сверяет закреплённый ключ и подпись, добавляет роль, свой публичный
   ключ, свежий nonce и эфемерный key; подписывает весь transcript.
3. Broker сверяет ключ именно для заявленной роли и подписывает подтверждение
   полного transcript. Повтор handshake из другой сессии не принимается.
4. Стороны подтверждают владение новым сессионным ключом зашифрованными
   CLIENT_READY / SERVER_READY. Только после этого доступны данные и команды.
5. Все сообщения шифруются X25519 / XSalsa20-Poly1305 через TweetNaCl 1.0.3.
   Nonce разделяет направления и включает последовательный счётчик.
   Повтор, перестановка, отражение, подмена и plaintext закрывают соединение.

Криптография включается установщиком из закреплённой npm-зависимости, без CDN.
Browser-реализация использует `crypto.getRandomValues`; `crypto.subtle` не нужен.
При отсутствии безопасного источника случайности соединение не устанавливается.
Старый HMAC-протокол остался только в низкоуровневом классе для прежних тестов;
продуктовый MCP/broker/UI его не используют и не переходят на него при ошибке.

## Доступ сессий

Broker отличает ключ MCP от ключа UI. UI не может вызывать broker RPC, MCP не
может выдавать себя за Figma-файл. Все аутентифицированные MCP-сессии этой установки
видят список подключённых файлов. Постоянного владельца файла нет: простое чтение
не мешает следующему чату. Если файлов несколько, необходимо указать fileKey —
активный файл другого чата не выбирается молча. `inspect_selection` с `includeFiles`
без fileKey сначала получает статус: при нуле или нескольких файлах возвращает
список, `selectionInspected: false` и `requiresFileKey`, не обращаясь к холсту.
При одном файле сохраняется обычное чтение выделения.

Для каждого fileKey broker ставит execute и captureScreenshot в общую очередь.
Следующая команда отправляется после получения результата или ошибки предыдущей.
Разные файлы независимы; status не ждёт очереди. Ожидание места ограничено пятью
секундами. Истёкшие запросы отклоняются до отправки и не выполняются позднее.
Закрытие MCP-транспорта отменяет ещё не отправленные команды этой сессии;
уже отправленная команда удерживает очередь до ответа или ошибки.

Очередь не даёт транзакционной изоляции всей задачи: доверенные чаты могут
последовательно менять один файл. Она также не отменяет уже отправленный код
в Figma при сетевом тайм-ауте. После неопределённого результата записи сначала
проверьте макет, а не повторяйте запись автоматически.

После потери соединения следующий запрос MCP создаёт новый защищённый канал с
повторной проверкой identity. Отправленные команды завершаются ошибкой и никогда
не переигрываются; неопределённая запись остаётся `unknown`. Явное закрытие MCP и
отказ аутентификации окончательны для клиента. Только `status` допускает один
автоматический повтор после обрыва. Обнаружение broker ограничено шестью секундами,
ответ статуса — пятью; ошибки прав и доверия возвращаются без цикла перезапусков.

При `status` broker сравнивает ревизию собственных модулей с диском. Если она
изменилась, он завершает себя после ответа, а MCP автоматически запускает свежий
процесс. Активные и ожидающие команды, а также неизвестный результат операции
откладывают обновление (`maintenance.state: deferred`). Неизвестность снимается
успешным проверочным чтением соответствующего файла. С момента решения об
обновлении новые команды отклоняются с `BRIDGE_RESTARTING` и `not_applied`.
Изменение MCP-схем не требует обновления broker. Старые версии без этого механизма
нужно один раз перезапустить вместе с MCP. Broker по-прежнему завершается через
60 секунд после закрытия всех MCP-сессий.

`get_status({fileKey})` ждёт регистрацию конкретной цели в оставшейся части
первых пяти секунд жизни broker и возвращает `target.connected`. Без fileKey
статус собирает список всё стартовое окно, включая файлы, подключившиеся позже
первого. У зрелого broker и уже зарегистрированной явной цели задержки нет.
Отсутствие цели даёт `TARGET_FILE_NOT_CONNECTED`; это не доказательство того,
что пользователь не запустил плагин. Одно адресное чтение проверяет назначение.
Для операции с явным `fileKey` действует такое же стартовое ожидание цели.

Для обычного старта достаточно одного `get_status`: `diagnostics.ready`, `state`,
`nextAction`, `current` и `issues` заменяют ручное сравнение хешей. `ready` проверяет
соединение и версии, но не заменяет проверку Plugin API внутри команды. Полные
проверки установщика и PNG не нужны на каждом старте. Загруженный код MCP и
каталог инструментов обновляются переподключением MCP в клиенте; плагин Figma —
повторным открытием его персональной сборки.

## Граница защиты и проверка

Защищаемся от посторонних веб-страниц, процессов без ключей установки, другой
обычной учётной записи ОС, подмены локального сервера и сообщений, смешения ролей
и перемешивания одновременно отправленных команд разных MCP-сессий. Чаты одной
доверенной установки не являются отдельными границами доступа к файлам.

Полный доступ к учётной записи владельца, администратор, вредоносные изменения
исходников или персонального UI находятся вне этой границы. Сохраняемые ключи
увеличивают срок последствий их кражи по сравнению с кодом, жившим только в
памяти. Удобство автоподключения не является доказательством полного сохранения
прежней модели угроз. Независимый криптографический аудит протокола не проводился.

`npm test` проверяет подписи, шифрование, отказ чужому ключу/роли/порту,
подмену сервера, replay и reflection, файловые права, обновление установки,
очередь команд, отмену ожидающих запросов, общий доступ и список файлов через
настоящий stdio MCP, полный сгенерированный UI
в VM с имитацией Figma postMessage, Pause/Resume и работу без crypto.subtle.
VM не заменяет проверку в настоящем Figma Desktop. Windows ACL необходимо
дополнительно проверить на Windows; текущая среда разработки — macOS.

Для отзыва ключей остановите AI-приложения и broker, закройте UI, удалите
персональный каталог и повторите установку и импорт manifest.
