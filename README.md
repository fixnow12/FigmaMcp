# FigmaMcp

**Редактируйте макеты Figma обычными словами — через Codex или OpenCode.**

FigmaMcp соединяет AI-ассистента с открытым файлом в Figma Desktop. В комплекте — локальный MCP-сервер и плагин **Figma Desktop Bridge — Auto**. Figma API-токен не нужен, подключение автоматическое.

## Возможности

- **Читать макет:** структуру слоёв, тексты, оформление, Auto Layout и скриншоты.
- **Редактировать:** менять тексты, цвета, шрифты, размеры и отступы; добавлять, копировать и перемещать блоки.
- **Создавать экраны:** с нуля или на основе существующего — в отдельном фрейме с редактируемыми слоями, сохраняя оригинал.
- **Работать с дизайн-системой:** находить стили и переменные, привязывать Variables, вставлять экземпляры локальных и библиотечных компонентов.
- **Настраивать интерактивность:** ссылки в тексте, переходы между экранами, оверлеи, прокрутку к блоку и действия «назад»/«закрыть». Пакетная проверка без записи и откат при ошибке.
- **Получать ресурсы:** экспортировать иконки в SVG и исходные изображения из заливок.
- **Подключать несколько файлов:** укажите нужный по названию или ссылке. Команды к одному файлу выполняются по очереди.

В окне Bridge видны состояние подключения, текущая операция и журнал с результатами и длительностью. Журнал можно экспортировать.

## Установка

Понадобятся **macOS или Windows 10/11**, [Node.js 20+](https://nodejs.org/), [Git](https://git-scm.com/), Figma Desktop и Codex либо OpenCode. Для автоматической установки в Codex команда `codex` должна быть доступна в терминале.

### 1. Скачайте проект и запустите установщик

В Terminal на macOS или PowerShell на Windows:

```bash
git clone https://github.com/fixnow12/FigmaMcp.git
cd FigmaMcp
```

**macOS:**

```bash
bash scripts/install.sh
```

**Windows:**

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

Установщик загрузит зависимости, выполнит проверки, подготовит плагин Figma и зарегистрирует плагин Codex, если найдёт команду `codex`.

### 2. Добавьте плагин в Figma

В Figma Desktop откройте **Plugins → Development → Import plugin from manifest…** и выберите `manifest.json` по пути из установщика:

- **macOS:** `~/.figma-local-bridge/figma-plugin/manifest.json` — нажмите `⌘⇧G` в диалоге выбора файла и вставьте путь;
- **Windows:** `%USERPROFILE%\.figma-local-bridge\figma-plugin\manifest.json`.

Импорт нужен один раз. Используйте персональный `manifest.json`, а не `manifest.template.json` из исходников.

### 3. Подключите AI-ассистента

**Codex:** после установки перезапустите приложение, откройте папку `FigmaMcp` и создайте новую задачу. MCP добавляется вместе с плагином.

<details>
<summary>Если регистрация плагина Codex была пропущена</summary>

Убедитесь, что команда `codex` доступна, и выполните из корня проекта:

```bash
codex plugin marketplace add .
codex plugin add figma-local-bridge@figma-mcp
```

Перезапустите Codex и создайте новую задачу. Отдельная регистрация через `codex mcp add` не нужна.

</details>

**OpenCode:** откройте корневую папку `FigmaMcp`, где лежит `opencode.json`, и создайте новый чат. MCP уже настроен в проекте.

### 4. Начните работу

Откройте нужный файл в Figma и запустите **Plugins → Development → Figma Desktop Bridge — Auto**. Оставьте окно плагина открытым, выделите фрейм и напишите ассистенту:

> Прочитай выделение в Figma и покажи скриншот.

При первом обращении Bridge подключится автоматически. Коды и ручное сопряжение не нужны.

Для проверки старта достаточно `get_status`: он сразу сообщает готовность и следующий
шаг при проблеме. После обрыва MCP восстанавливает соединение; устаревший broker
обновляется автоматически при проверке статуса, когда операции завершены. Отправленные
изменения не повторяются. Проверки всей установки нужны после установки/обновления,
а не перед каждой задачей. После перехода со старой версии один раз переподключите MCP;
при изменении самого MCP повторное подключение загружает новые команды.

Автообновление broker отслеживает изменения файлов в каталоге, из которого он
запущен. Если Codex установил новую версию в отдельный каталог кэша, старому broker
нужен разовый перезапуск по инструкции ниже. Статус с `fileKey` проверяет готовность
выбранного файла; старые плагины в других файлах не блокируют эту проверку.

## Примеры запросов

> Замени текст кнопки на «Продолжить» и сделай отступы по 16 px.

> Проверь Auto Layout выделенного блока и исправь отступы.

> Воссоздай выделенный экран рядом в отдельном фрейме, сохрани шрифты и оформление. Оригинал не меняй.

> Создай вариант этого экрана: замени список способов оплаты кнопкой «Продолжить», а заголовок — на «Поддержать фонд».

> Сделай пункты оглавления ссылками на соответствующие экраны, а кнопку «Помощь» — ссылкой на сайт.

Названия MCP-команд и JSON знать не нужно. При воссоздании экземпляры становятся обычными фреймами, а привязки к Variables — текущими значениями. Маски, повороты групп и отражённые векторы с исходными контурами поддерживаются. Видеозаливки, Grid, skew и отражённые контейнеры пока блокируют реконструкцию; результат нужно сверять со скриншотом исходника.

Подробности [ссылок и прототипных переходов](plugins/figma-local-bridge/skills/figma-local/references/interactions.md), ограничения и [идеи дальнейшего развития](docs/functionality-roadmap.md).

## Обновление и помощь

В папке проекта выполните `git pull` и повторите команду установки для своей ОС. Затем закройте Bridge и все AI-приложения, использующие этот MCP, подождите минуту и откройте их заново. Начните новый чат или задачу. Повторный импорт manifest при прежнем пути не нужен.

Если соединения нет, проверьте, что Bridge запущен в нужном файле, и нажмите **Подключить**. Попросите ассистента проверить состояние `figma-local` через `get_status`. Если инструментов MCP вообще нет, повторите установку и перезапустите AI-приложение.

После тайм-аута сначала проверьте макет: изменение могло выполниться. Подробности диагностики и журнала — в [документации Bridge](plugins/figma-local-bridge/src/figma-plugin/README.md).

## Проверка проекта

Из корня репозитория:

```bash
npm test --prefix plugins/figma-local-bridge
npm run schema:check --prefix plugins/figma-local-bridge
npm run verify --prefix plugins/figma-local-bridge
node plugins/figma-local-bridge/scripts/verify-install.mjs --opencode
node scripts/validate-repo.mjs
npm audit --prefix plugins/figma-local-bridge
```

Тесты проверяют операции и откат на поведенческой модели Figma, локальные соединения, установку и запуск. Они не заменяют проверку реального рендеринга в Figma. Windows-путь запуска проверяется в CI на Windows; локально на macOS запускается macOS-путь. `schema:check` обнаруживает устаревшую опубликованную схему без перезаписи файла.

После обновления и перезапуска Bridge проверьте работающие версии: `node plugins/figma-local-bridge/scripts/verify-install.mjs --opencode --require-current`. Команда проверяет соединение, ревизии MCP, broker и плагина в каждом подключённом файле, затем читает выделение. Без подтверждения текущих ревизий она завершается с ошибкой. Обычная проверка `--live` также показывает диагностику и `runtimeCurrent`, но допускает чтение через старую сборку. CI отклоняет зависимости с уязвимостями средней тяжести и выше.

Если реконструкция остановилась, ответ `RECONSTRUCTION_BLOCKED` содержит список `blockers` с именами и ID слоёв. Явно удаляемые или заменяемые через `changes` ветки не требуют экспорта и загрузки своих шрифтов; это относится только к новой сборке.

## Подключение и данные

Мост работает локально через `127.0.0.1`, с проверкой ключей и шифрованием соединения. Обработка данных AI зависит от выбранного ассистента и модели. Персональный каталог `~/.figma-local-bridge` содержит ключи — не публикуйте и не пересылайте его. Закрытие окна Bridge отключает доступ к файлу через этот плагин. [Подробнее о безопасности](plugins/figma-local-bridge/AUTO_CONNECTION.md).
