# FigmaMcp

**Меняйте макеты в Figma, просто описывая задачу в чате.**

FigmaMcp подключает Codex или OpenCode к открытому файлу Figma. Вы пишете, что нужно сделать, а ассистент читает макет и вносит изменения.

Например:

> Замени текст кнопки на «Продолжить», увеличь её высоту до 48 px и выровняй по центру экрана.

## Что можно делать

- Менять тексты, цвета, шрифты, размеры и отступы.
- Настраивать Auto Layout, копировать блоки и собирать новые экраны.
- Использовать доступные компоненты, стили и переменные вашей дизайн-системы.
- Добавлять ссылки и переходы между экранами.
- Переключать страницы, менять их фон и обложку файла.
- Экспортировать иконки и изображения.

## Что понадобится

- Компьютер с **macOS или Windows 10/11**.
- **Figma Desktop** — установленное приложение Figma.
- **Codex или OpenCode** — выберите тот, которым пользуетесь.
- [Node.js 20 или новее](https://nodejs.org/) и [Git](https://git-scm.com/) — программы, необходимые для установки.

## Как установить

### 1. Скачайте проект

Откройте **Терминал** на macOS или **PowerShell** на Windows. Выполните две команды по очереди:

```bash
git clone https://github.com/fixnow12/FigmaMcp.git
cd FigmaMcp
```

### 2. Запустите установку

**На macOS:**

```bash
bash scripts/install.sh
```

**На Windows:**

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

Дождитесь сообщения **«Готово»**. Установщик подготовит плагин Figma и покажет путь к файлу `manifest.json`. Этот файл понадобится на следующем шаге.

### 3. Добавьте плагин в Figma

В Figma Desktop выберите **Plugins → Development → Import plugin from manifest…** и откройте `manifest.json` по пути, который показал установщик.

Обычно он находится здесь:

- **macOS:** `~/.figma-local-bridge/figma-plugin/manifest.json`. В окне выбора файла нажмите `⌘⇧G` и вставьте путь.
- **Windows:** `%USERPROFILE%\.figma-local-bridge\figma-plugin\manifest.json`.

Это нужно сделать один раз. Выбирайте подготовленный установщиком файл, а не `manifest.template.json` из папки проекта.

### 4. Откройте ассистента

**Codex:** перезапустите приложение, откройте в нём папку `FigmaMcp` и создайте новую задачу.

<details>
<summary>Установщик сообщил, что Codex не найден</summary>

Для автоматического подключения команда `codex` должна быть доступна в терминале. Когда она будет доступна, выполните из папки `FigmaMcp`:

```bash
codex plugin marketplace add .
codex plugin add figma-local-bridge@figma-mcp
```

Затем перезапустите Codex и создайте новую задачу.

</details>

**OpenCode:** откройте папку `FigmaMcp` и создайте новый чат. Настройки подключения уже лежат в этой папке, в файле `opencode.json`.

## Как начать работу

1. Откройте нужный макет в Figma Desktop.
2. Запустите **Plugins → Development → Figma Desktop Bridge — Auto** и оставьте окно плагина открытым.
3. Выделите экран или блок, с которым хотите работать.
4. Напишите в Codex или OpenCode:

> Прочитай выделение в Figma и покажи скриншот.

Если ассистент показал нужный макет, можно давать задания. Подключение происходит автоматически — отдельный токен Figma вводить не нужно.

Для работы с несколькими файлами запустите плагин в каждом. В запросе укажите ссылку на нужный файл.

## Что можно попросить

> Сделай одинаковые отступы между карточками — по 16 px.

> Проверь Auto Layout выделенного блока и исправь выравнивание.

> Создай рядом новый вариант этого экрана с заголовком «Поддержать фонд». Оригинал не меняй.

> Сделай пункты оглавления ссылками на соответствующие экраны.

> Экспортируй выделенные иконки в SVG.

## Что важно знать

- **Проверяйте результат в Figma.** Ассистент может неверно понять задачу или воспроизвести оформление с отличиями.
- **Воссоздание экрана отличается от копирования.** При воссоздании связи с компонентами и переменными не сохраняются: получаются обычные слои с текущим оформлением. При обычном копировании блоков эти связи сохраняются.
- **Некоторые элементы нельзя воссоздать**, например видеозаливки. Подробнее — в [ограничениях воссоздания](plugins/figma-local-bridge/skills/figma-local/references/reconstruction.md).
- **Компоненты и стили библиотек должны быть доступны вашему аккаунту.** Полный поиск по всем внешним библиотекам не поддерживается. Правку исходных библиотечных компонентов нужно согласовать отдельно.
- **Имя файла меняется вручную в Figma.** Ассистент может прочитать его и установить обложку.

## Если что-то не работает

Убедитесь, что плагин открыт именно в нужном файле Figma. Нажмите в нём **«Подключить»** и попросите ассистента:

> Проверь подключение к этому файлу через figma-local.

Если ассистенту недоступен инструмент Figma, повторите установку и перезапустите Codex или OpenCode.

Если запрос прервался, сначала посмотрите на макет: изменение могло уже выполниться. Проверьте результат перед повтором.

Дополнительные проверки — в [руководстве по обслуживанию](docs/maintenance.md).

## Как обновить

В папке `FigmaMcp` выполните:

```bash
git pull --ff-only
```

Повторите команду установки для вашей ОС. Закройте плагин Figma и использующие его AI-приложения, подождите минуту и откройте их заново. Создайте новый чат или задачу. Если путь к `manifest.json` не изменился, повторно добавлять его в Figma не нужно.

## Что происходит с данными

Подключение к Figma работает на вашем компьютере. Но то, где и как модель обрабатывает данные макета, зависит от выбранного ассистента и его настроек.

Папка `.figma-local-bridge` в домашнем каталоге содержит ключи подключения. Не публикуйте и не пересылайте её. Закрытие окна плагина отключает его доступ к файлу. [Подробнее о подключении и безопасности](plugins/figma-local-bridge/AUTO_CONNECTION.md).
