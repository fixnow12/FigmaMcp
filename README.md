# FigmaMcp

FigmaMcp позволяет OpenCode Desktop работать с открытым файлом в Figma Desktop: читать выделение, менять элементы, создавать экраны и использовать компоненты.

Всё работает локально на вашем компьютере. Figma API-токен, браузерная автоматизация и облачный сервер не нужны.

## Что умеет

- читать выделенный элемент и делать его скриншот;
- менять текст, цвет, размер, отступы и другие свойства;
- добавлять новые элементы внутрь существующих;
- создавать целые экраны;
- вставлять локальные и библиотечные компоненты;
- работать с несколькими открытыми файлами Figma.

В текущей разработке добавлены подробное чтение оформления, изменение типографики и Auto Layout, вставка компонентов по ID и отдельная проверка подключения `get_status`.

Также доступны копирование готовых блоков (`clone_nodes`), перенос и перестановка слоёв (`move_nodes`), поиск элементов и ресурсов дизайн-системы (`find_assets`) и настоящие привязки к доступным в файле Variables (`bind_variables`). Поиск не импортирует ресурсы; значения библиотечных переменных остаются неизменными.

Пакетные правки проверяют цели и шрифты до записи и при ошибке пытаются восстановить исходные свойства. Результат скриншота возвращается отдельно: если правка выполнена, а экспорт снимка не удался, повторять правку не нужно. После тайм-аута или обрыва связи сначала проверьте макет — результат команды может быть неизвестен.

## Установка для OpenCode Desktop

Понадобятся:

- [Node.js](https://nodejs.org/) версии 20 или новее;
- Figma Desktop;
- OpenCode Desktop;
- macOS или Windows 10/11.

### 1. Скачайте и установите FigmaMcp

Откройте Terminal на macOS или PowerShell на Windows.

```bash
git clone https://github.com/fixnow12/FigmaMcp.git
cd FigmaMcp
```

На macOS выполните:

```bash
chmod +x scripts/install.sh
./scripts/install.sh
```

На Windows выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

Установщик загрузит зависимости и проверит, что всё работает.

### 2. Добавьте Bridge в Figma Desktop

Это нужно сделать один раз.

1. Откройте Figma Desktop.
2. Выберите **Plugins → Development → Import plugin from manifest…**.
3. Откройте **«Плагин Figma»** в корне проекта и выберите **manifest.json**. Это ярлык на единственную рабочую сборку. Если ярлыка нет, используйте путь, который напечатал установщик:
   - macOS: `~/.figma-local-bridge/figma-plugin/manifest.json`;
   - Windows: `%USERPROFILE%\.figma-local-bridge\figma-plugin\manifest.json`.

В диалоге macOS нажмите `⌘⇧G`, чтобы перейти в скрытый каталог. Плагин называется **Figma Desktop Bridge — Auto**. При обновлении установщик обновляет эту же сборку, сохраняя путь и настройки подключения.

Для разработки исходники находятся в `plugins/figma-local-bridge/src/figma-plugin`. `manifest.template.json` — внутренний файл сборки, а не второй плагин для импорта. Установщик добавляет персональные данные автоподключения только в рабочую сборку вне репозитория.

### 3. Откройте проект в OpenCode Desktop

1. Откройте в OpenCode Desktop корневую папку `FigmaMcp`.
2. Убедитесь, что в ней виден файл `opencode.json`.
3. Создайте новый чат.

OpenCode автоматически запустит локальное подключение `figma-local`. Отдельно настраивать MCP не нужно.

### 4. Подключите нужный файл Figma

1. Откройте нужный макет в Figma Desktop.
2. Запустите **Plugins → Development → Figma Desktop Bridge — Auto**.
3. Оставьте маленькое окно Bridge открытым.
4. Выделите элемент и попросите OpenCode проверить его, например:

> Проверь выделение в Figma.

Bridge подключится автоматически при первом обращении AI к Figma. Ничего копировать, вводить или подтверждать не нужно. Дождитесь статуса «Подключено — AI может работать с файлом».

При обновлении с версии 0.2.2 один раз импортируйте новый персональный manifest и перезапустите AI-приложение. Старое окно Bridge закройте.

## Как работать

Оставляйте окно Figma Desktop Bridge открытым, пока OpenCode работает с макетом. Обычно достаточно выделить нужный элемент в Figma и описать результат обычными словами.

Примеры:

> Сделай выделенную кнопку красной и покажи скриншот результата.

> Замени текст на «Продолжить» и увеличь внутренние отступы.

> Добавь рядом вторичную кнопку.

> Проверь структуру выделенного блока и исправь Auto Layout.

> Воссоздай этот экран в отдельном фрейме, сохрани исходные шрифты и оформление.

> Собери почти такой же экран, но замени список способов оплаты кнопкой «Продолжить» и поменяй заголовок на «Поддержать фонд».

Названия команд и JSON знать не нужно. Агент сам выбирает исходный экран и нужные слои, а плагин читает дерево, собирает новый фрейм и применяет изменения. Поддержаны изменение текста и оформления, удаление, замена и добавление блоков. План и шрифты проверяются до создания; оригинал сохраняется.

Для воссоздания исходника `recreate_screen` читает его дерево и создаёт новые редактируемые слои без копирования узлов. Модель передаёт `sourceId` и `fileKey`; переписывать свойства экрана вручную не требуется. Команда сохраняет видимое состояние, исходные контуры и изображения, затем проверяет геометрию и текст. `dryRun: true` проверяет готовность без создания. Скрытые ветки исключаются; экземпляры становятся фреймами, библиотечные связи и Variables заменяются текущими значениями. Маски, Grid, сложные трансформации и недоступные шрифты останавливают сборку. Сравнение PNG остаётся необходимым: проверка структуры не доказывает пиксельного совпадения.

Если открыто несколько файлов, `inspect_selection` без `fileKey` автоматически вернёт список подключений без ошибки и без чтения холста. AI выберет файл по ссылке или названию из вашего запроса и передаст его `fileKey`; если цель не указана, уточнит её. Перебирать выделения для выбора файла не нужно: они могут сохраняться в нескольких вкладках. Чтение и редактирование не закрепляют файл за чатом. Команды разных чатов к одному файлу выполняются по очереди; разные файлы могут обрабатываться параллельно. Ожидание очереди ограничено пятью секундами: при превышении команда отклоняется до отправки в Figma. Повторить её можно после завершения текущей операции.

Очередь разделяет отдельные команды, а не целые задачи: два чата могут по очереди менять один макет. Не поручайте им одновременно противоречащие друг другу изменения.

## Если не подключается

Проверьте четыре вещи:

1. В OpenCode открыта именно корневая папка `FigmaMcp`, а не её подпапка.
2. В Figma Desktop открыт нужный файл.
3. В этом файле запущен **Figma Desktop Bridge — Auto**.
4. Импортирован **Bridge — Auto** из персонального каталога, а не исходный шаблон.

Нажмите **Подключить** в Bridge. Если требуется новая установка, повторите установщик и импорт manifest. Порт `9233` должен быть свободен для Bridge: занятый посторонней программой порт не обходится подключением без проверки ключей.

## А что с Codex

В Codex работа устроена почти так же: запустите установщик, перезапустите Codex, откройте папку `FigmaMcp`, запустите **Bridge — Auto** в Figma. Сопряжение выполняется автоматически.

Если автоматическая установка Codex-плагина не сработала, выполните из корня репозитория:

```bash
codex plugin marketplace add .
codex plugin add figma-local-bridge@figma-mcp
```

Плагин уже добавляет MCP-сервер `figma-local`; отдельно регистрировать его через `codex mcp add` не нужно. Если ранее вы вручную добавили **тот же мост** под именем `figma-local`, после установки плагина удалите дублирующую запись:

```bash
codex mcp remove figma-local
```

После обновления откройте новый чат. Для перехода со старого broker с постоянными блокировками один раз перезапустите AI-приложение и broker. Перезапуск только окна плагина Figma не обновляет код broker.

### Проверка подключения Codex

Установщик останавливается при ошибке регистрации или обновления, даже если старая версия уже установлена. После установки он сверяет исходники с кэшем Codex и запускает именно установленную копию командой из `.mcp.json`.

Для отдельной проверки из корня проекта:

```bash
node plugins/figma-local-bridge/scripts/verify-codex-install.mjs --live --screenshot
```

Проверка читает выделение в подключённых файлах и получает PNG; макет не меняется. Для PNG выделите фрейм хотя бы в одном файле. Без `--live` проверяется только запуск и список инструментов, а не связь с Figma.

Если инструментов `figma-local` вообще нет в задаче, сначала проверьте запуск MCP. `No such file or directory` означает проблему команды запуска или каталога установленного плагина; повторный запуск окна Figma её не исправляет. Если проверка установленной копии успешна, перезапустите MCP в настройках Codex и откройте новую задачу: старой задаче мог достаться каталог инструментов от неудачного запуска. Сам факт наличия skill не доказывает доступность MCP.

## Версии

- FigmaMcp и Figma Desktop Bridge: **0.3.0**;
- минимальная версия Node.js: **20**;
- Figma Desktop Bridge основан на `figma-console-mcp@1.40.0`, но работает независимо от него;
- внешний Cloud Mode из исходного проекта удалён — эта версия подключается только локально.

## Безопасность

Bridge слушает `127.0.0.1:9233`. Установщик создаёт разные ключи для сервера, Figma-плагина и MCP-клиента. Стороны проверяют подписи Ed25519, а сообщения шифруются отдельным ключом каждой сессии с защитой от подмены и повторной отправки. До завершения проверки сведения о файле и команды заблокированы.

Ключи и персональная сборка находятся только в `~/.figma-local-bridge`: права `0700/0600` на macOS, ACL текущего пользователя и SYSTEM на Windows. Это файловая защита ОС, **не Keychain и не шифрование ключей на диске**. Плагин должен прочитать свой ключ при запуске; `clientStorage` для ключей не используется. Не публикуйте и не пересылайте персональный каталог. На другом компьютере запускайте установщик заново.

Автоподключение означает доверие этой установке в рамках вашей учётной записи ОС. Оно защищает от постороннего сайта, сервера без ключа и другой учётной записи с обычными правами. Программа с полным доступом к вашей учётной записи, администратор и подмена исходников установки находятся вне этой границы защиты. В отличие от старой версии, ключи теперь сохраняются на диске; это осознанное изменение модели доверия, а не обещание полной эквивалентности эфемерному коду.

Обновление сохраняет ключи. Для отзыва доверия: закройте Bridge и AI-приложения, остановите локальный broker, удалите персональный каталог и повторите установку. Старую персональную сборку после этого не используйте.

Протокол и проверенные сценарии описаны в [документе об автоподключении](plugins/figma-local-bridge/AUTO_CONNECTION.md).
