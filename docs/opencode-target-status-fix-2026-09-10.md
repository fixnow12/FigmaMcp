# OpenCode: преждевременное отсутствие Untitled

Источник: новый экспорт `iomoney-guide-constructor-skill-workflow.json`, сессия `ses_f73e308a4ffegRN13oCbOfwBVd`, и скриншот открытого Untitled с зелёным Figma Desktop Bridge. Утверждение, что пользователь не открыл целевой файл или плагин, не подтверждено. Предыдущее объяснение фоновой вкладкой не установило причину этого случая.

## Причина

OpenCode вызвал только `figma-local_get_status({})`. Broker стартовал в 16:26:43.275 UTC; IO Material зарегистрировался в 16:26:43.691; ответ завершился в 16:26:43.697. Общий статус закончил стартовое ожидание после первого файла. Агент принял неполный стартовый список за доказательство отсутствия Untitled и не вызвал адресное чтение `<FILE_KEY> / 0:1`.

Предыдущая правка ожидала конкретный файл только внутри операций `runInFile`. Публичный `get_status` не принимал fileKey и возвращался при любом подключённом файле. Инструкции не требовали адресного чтения перед просьбой запустить уже открытый плагин.

## Исправление

- Общий статус собирает список до конца оставшейся части первых пяти секунд жизни broker. При известном fileKey завершает ожидание после регистрации именно этого файла. Зрелый broker отвечает сразу.
- MCP публикует необязательный `get_status.fileKey`, возвращает `target.connected`, а `diagnostics.ready` не подтверждает отсутствующую цель.
- Инструкции Bridge и GuideConstructor требуют использовать известный fileKey и проверить назначение адресным чтением. Зелёный открытый плагин нельзя объявлять закрытым по раннему общему снимку.

## Проверка

Регрессионный тест: чужой файл зарегистрирован сразу, целевой — через четыре секунды. До исправления общий статус возвращал только чужой файл; после — оба. Проверены схема MCP, отсутствующая и присутствующая цели, отсутствие команд холсту при статусе. Все 209 тестов прошли; JSON Schema и git diff --check прошли.

Живая проверка проведена через сам OpenCode, проект GuideConstructor, GLM-5.3-Flash, сессия `ses_f73cf09e4ffeLysZr5s0XvXFsc`:

- `figma-local_get_status({fileKey:"<FILE_KEY>"})`: target.connected true, diagnostics READY, все current true, issues пусто.
- `figma-local_inspect_selection({fileKey:"<FILE_KEY>",nodeId:"0:1",depth:1,maxNodes:10})`: operationStatus read, missing пусто, coverage complete, Page 1 без детей.

В этой проверке вкладки Figma не переключались и плагин не перезапускался. OpenCode перезапущен для загрузки нового MCP-каталога; успешный результат открыт в приложении. Проверка не создавала слайды и не доказывает визуальную готовность гайда.

Два первых запуска диагностического CLI завершились до MCP-вызовов: CLI выбрал недоступную модель openai/gpt-4o. Проверка продолжена в той же диагностической сессии с моделью GLM из пользовательского лога; настройки модели проекта не менялись.
