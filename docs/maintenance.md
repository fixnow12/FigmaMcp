# Обслуживание FigmaMcp

Техническая справка по проверке установки, обновлению и восстановлению соединения. Начальная установка и первый запрос описаны в [README](../README.md).

## Проверка подключения

Для начала работы достаточно попросить ассистента вызвать `get_status` для нужного файла. Статус сообщает готовность и следующий шаг при проблеме. Вызов с точным `fileKey` проверяет выбранный файл; старые плагины в других файлах не блокируют эту проверку.

Наличие MCP-команд в ассистенте ещё не подтверждает подключение к файлу. После статуса прочитайте выделение и получите скриншот. Проверки всей установки нужны после установки или обновления, а не перед каждой задачей.

## Обновление и восстановление соединения

1. Из корня репозитория выполните `git pull --ff-only`. Если Git сообщает о конфликте с локальными изменениями или расхождении веток, сначала разберите состояние репозитория, сохранив свою работу.
2. Повторите установщик для своей ОС: `bash scripts/install.sh` на macOS или `powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1` на Windows.
3. Закройте Bridge и все AI-приложения, использующие этот MCP. Подождите минуту и откройте их заново.
4. Запустите **Figma Desktop Bridge — Auto** в нужном файле. При прежнем пути повторный импорт персонального manifest не нужен.
5. Создайте новую задачу Codex или чат OpenCode, проверьте статус файла и прочитайте выделение.

После обрыва MCP восстанавливает соединение без автоматического повтора отправленных изменений. Локальный broker — процесс, который связывает MCP и плагин Figma — обновляется при проверке статуса, когда операции завершены.

Автообновление broker отслеживает изменения в каталоге, из которого он запущен. Если Codex установил новую версию в отдельный каталог кэша, старому broker нужен разовый перезапуск по шагам выше. После изменения самого MCP переподключение загружает новые команды.

Если соединения нет, убедитесь, что Bridge открыт в нужном файле, и нажмите **Подключить**. Если инструменты MCP отсутствуют в ассистенте, повторите установку и перезапустите AI-приложение.

## Тайм-ауты и остановленные операции

После тайм-аута изменение могло выполниться. Дождитесь завершения текущей операции, прочитайте затронутые слои и проверьте макет. Не повторяйте запись с неизвестным результатом автоматически.

Для изменения обложки проверьте результат через `get_file_metadata` с тем же точным `fileKey`. Правила переключения страниц, проверки имени и изменения обложки приведены в [справочнике контекста файла](../plugins/figma-local-bridge/skills/figma-local/references/file-context.md).

Если реконструкция остановилась, ответ `RECONSTRUCTION_BLOCKED` содержит список `blockers` с именами и ID слоёв. Повтор того же вызова не устраняет причину. Явно удаляемые или заменяемые через `changes` ветки не требуют экспорта и загрузки своих шрифтов; это относится только к новой сборке. Подробнее — в [справочнике реконструкции](../plugins/figma-local-bridge/skills/figma-local/references/reconstruction.md).

Состояния операций, неполный откат и экспорт журнала описаны в [документации Bridge](../plugins/figma-local-bridge/src/figma-plugin/README.md).

## Проверка проекта

Все команды выполняются из корня репозитория:

```bash
npm test --prefix plugins/figma-local-bridge
npm run schema:check --prefix plugins/figma-local-bridge
npm run verify --prefix plugins/figma-local-bridge
node plugins/figma-local-bridge/scripts/verify-install.mjs --opencode
node scripts/validate-repo.mjs
npm audit --prefix plugins/figma-local-bridge
```

- `npm test` проверяет операции и откат на поведенческой модели Figma, локальные соединения, установку и запуск. Тесты не заменяют проверку реального рендеринга в Figma.
- `schema:check` обнаруживает устаревшую опубликованную схему без перезаписи файла.
- `verify` проверяет запуск MCP и схемы его инструментов; `--opencode` запускает эту проверку через конфигурацию OpenCode. Без `--live` или `--require-current` соединение с Figma не проверяется.
- `validate-repo.mjs` проверяет структуру, переносимость и наличие признаков секретов.
- `npm audit` проверяет зависимости. CI отклоняет уязвимости средней тяжести и выше.

Windows-путь запуска проверяется в CI на Windows; локально на macOS запускается macOS-путь.

## Проверка работающих версий

После обновления и перезапуска Bridge выполните:

```bash
node plugins/figma-local-bridge/scripts/verify-install.mjs --opencode --require-current
```

Команда проверяет соединение, ревизии MCP, broker и плагина в каждом подключённом файле, затем читает выделение. Без подтверждения текущих ревизий она завершается с ошибкой.

Проверка с `--live` также показывает диагностику и `runtimeCurrent`, но допускает чтение через старую сборку:

```bash
node plugins/figma-local-bridge/scripts/verify-install.mjs --opencode --live
```

Успешное чтение через старую сборку не подтверждает, что обновление применилось. Проверка ревизий, чтение структуры и визуальная проверка макета подтверждают разные свойства результата.
