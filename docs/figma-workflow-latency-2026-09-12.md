# Скорость MCP: полный вызов и пакетная правка

Дата: 2026-09-12. Проверка выполнена через типизированный MCP `figma-local`,
подключённый к Figma Desktop. Исходная сборка —
`0.3.0+codex.20260912-sizing-3`, исправленная и установленная —
`0.3.0+codex.20260912-latency-1`.

## Исправленная задержка завершения

Диагностический `scripts/call-tool.mjs` открывает MCP-процесс, получает каталог,
вызывает инструмент и закрывает клиент. В используемом SDK серверный stdio
transport не обрабатывает EOF входного потока. Соединение с broker удерживало
процесс после завершённого ответа. Клиент ждал 2000 мс и посылал SIGTERM.

В `src/server.mjs` EOF теперь вызывает существующий `shutdown()`:
закрываются MCP transport и соединение только этой сессии с Bridge.
Принудительного `process.exit()` на EOF нет. Общий broker продолжает работать.
Проверки макета и тайм-ауты операций не сокращались.

Медианы пяти независимых сессий, миллисекунды:

| Этап | До | После |
| --- | ---: | ---: |
| Запуск процесса и MCP handshake | 167,498 | 147,120 |
| Получение каталога | 7,701 | 7,649 |
| Полное чтение 8 узлов, без PNG | 154,048 | 144,309 |
| Закрытие клиента | 2016,195 | 8,378 |
| Суммарный цикл каждой сессии, медиана | 2344,689 | 309,477 |

Медиана суммы вычислена по каждому прогону, а не сложением медиан этапов.
В измерение не входят загрузка самого скрипта-бенчмарка, сохранение артефактов,
оболочка командного инструмента и работа модели. Разницу в запуске/чтении нельзя
приписывать исправлению EOF; устранённая задержка подтверждена отдельным тестом.

Все значения закрытия до: 2017,587; 2017,565; 2015,763; 2013,922; 2016,195.
После: 10,374; 18,290; 7,155; 6,517; 8,378.
Полные результаты чтения до и после совпали во всех пяти парах.

Это улучшение одноразового CLI и завершения сессий. Обычный постоянно
подключённый MCP не запускается и не закрывается на каждом обращении:
для него эти две секунды не были задержкой каждого инструмента.

## Одинаковая задача с меньшим числом вызовов

Назначение: ранее созданный диагностический экран `10:21`, 8 узлов,
1200 × 760, файл `5Yh7bqIB0OQczhoxOVSloL` (`Untitled`). Менялись три текста
`10:23`, `10:25`, `10:27`. Использовано одно постоянное MCP-подключение.

Обычный вариант: полное чтение → три одиночных `patch_nodes` → полное чтение
с PNG. Пакетный: такое же чтение → один `patch_nodes` с тремя правками → такое
же полное чтение с PNG. Во всех чтениях `depth:8`, `maxNodes:100`, `detail:full`.
Перед каждым прогоном тексты восстанавливались вне измеряемого цикла, а
начальное дерево сравнивалось с сохранённым исходным состоянием.

| Пара | Одиночные, 5 вызовов, мс | Пакет, 3 вызова, мс | Порядок |
| --- | ---: | ---: | --- |
| 1 | 405,348 | 216,745 | одиночные → пакет |
| 2 | 268,797 | 217,683 | пакет → одиночные |
| 3 | 274,789 | 240,279 | одиночные → пакет |
| 4 | 278,391 | 215,462 | пакет → одиночные |
| 5 | 298,917 | 215,699 | одиночные → пакет |
| Медиана | 278,391 | 216,745 | |

Сумма MCP round-trip длительностей уменьшилась на 22,1%, число обращений —
на 40%. Работа модели между инструментами в этот замер не входит. Пакетирование
существовало в API и до этой правки; здесь измерен эффект его использования.
Описание `patch_nodes` теперь явно рекомендует пакет для известных правок
одного файла с общей целью и общим откатом, сохраняя отдельные шаги там,
где следующее действие зависит от результата предыдущего.

Контроль качества: `coverage.complete:true` во всех чтениях; после всех десяти
прогонов полные деревья строго равны, PNG побайтово равны; изображения результата
и восстановления просмотрены. Тексты восстановлены, итоговое дерево совпало с
исходным. Защищённые исходники `10:3` и `10:12` прочитаны до/после и не изменились.
Это проверка трёх текстовых правок на небольшом экране; прототипных переходов
в задаче нет, `actualClicks:not-tested`.

## Граница между MCP и всей задачей

В журнале предыдущего завершённого этапа этой задачи (10:11:46–10:22:31 UTC)
прошло 644,575 с. Суммарные непересекающиеся интервалы от вызова до ответа
видимых инструментов — 70,806 с, оставшиеся промежутки — 573,769 с.
Это диагностика и разработка исправления, а не обычная сборка продуктового экрана.

Оставшиеся промежутки включают рассуждения, подготовку кода и ответов,
оркестрацию; асинхронные процессы могут продолжать работать после возврата
инструмента. Интервалы инструментов включают shell, тесты, проверки разрешений
и ревью. Поэтому эти числа не измеряют отдельно inference модели и не позволяют
приписать всю многоминутную длительность самому MCP. Ускорение всей реальной
задачи на выбранной пользователем модели пока не измерено.

## Проверка и установка

- Регрессионный тест сначала воспроизвёл SIGTERM после EOF; после исправления
  проходит и подтверждает, что другой MCP-клиент продолжает читать файл.
- Свежий полный прогон: 253/253 теста, включая статусы ошибок, очередь broker,
  неизвестные результаты записи и ошибки PNG.
- Тест EOF не проверяет доставку ответа незавершённого запроса после закрытия:
  EOF завершает сессию, `server.close()` отменяет обработчики MCP. Неизвестную
  запись после обрыва по-прежнему нужно прочитать, автоматического повтора нет.
- Установленная копия совпадает с исходниками: `cacheMatchesSource:true`;
  новый MCP-процесс: `runtimeCurrent:true`, `diagnostics.state:READY`.
  Уже запущенные старые MCP-процессы требуют переподключения.

Локальные исходные замеры, скрипты, JSON и PNG:
`/tmp/figma-workflow-benchmark-20260912/`. Этот временный каталог может быть
удалён системой; ключевые результаты сохранены в таблицах выше.

## Загрузка инструкций по сценарию

Следующий этап выполнен поверх сборки `20260912-template-1`, содержащей новые
команды библиотечных шаблонов и метаданных. В этой версии основной `SKILL.md`
составлял 25 941 символ. Независимая проверка простой задачи с тремя текстовыми
правками потребовала чтения всего входного файла; первая выдача обрезалась.
Агент дочитал её, включая не относящиеся к этой задаче специальные сценарии.

Пять разделов перенесены в тематические справки: воссоздание, готовые ресурсы,
связи, диагностика подключения, шаблоны и метаданные. Основная инструкция
содержит явные условия их чтения, защиту библиотек, ограничения чтения, проверку
PNG и обработку неизвестных результатов. Содержимое прежних разделов сохранено;
при переносе скорректированы относительные ссылки. Обычная текстовая правка
получает рекомендацию объединить изменения и финальное чтение с PNG.

Основной файл после разделения: 11 875 символов, на 54,2% меньше. Это сокращение
обязательного текста инструкции, не измерение времени или токенов модели.
Объём всех справок не уменьшен; сложная задача загрузит нужные ей разделы.
Код MCP и схема инструментов этим этапом не изменялись.

Независимая проверка маршрутов охватила текстовую правку, вариант экрана,
библиотечный шаблон и неизвестный результат append. Для текстовой правки агент
обошёлся основным SKILL, сохранил пакетную запись и итоговое full-чтение с PNG.
Для остальных сценариев нашёл тематические справки и сохранил запрет слепого
повтора unknown. Проверка была учебной, read-only, без выполнения команд Figma.

Дополнительно уточнены две прежние неоднозначности: `validate-spec.mjs` нужен
для `spec`, передаваемой `render_screen`; перед `recreate_screen` агент читает
композицию и цели изменений, а полный обход дерева выполняется внутри инструмента
с отказом при неполном чтении. При ручном переносе исходных свойств в `render_screen`
необходимо дочитать все переносимые свойства. Итоговая проверка не исключена.
Валидатор skill и проверка относительных ссылок прошли. Сборка инструкции:
`0.3.0+codex.20260912-context-1`.

## Реальная задача: экран перевода

Запрос пользователя: «создай экран перевода денег с суммой, получателем и
кнопкой». Создан новый редактируемый экран 390 × 844 в разрешённом пустом файле,
26 узлов с учётом внутренней структуры SVG. Полное чтение завершено, расхождений
с заданными текстами, шрифтами и геометрией не найдено, PNG просмотрен.

По журналу именно этого запуска: `gpt-6-astra`, reasoning effort `high`.
Эти настройки не менялись. По одному запуску влияние выбранного effort
на скорость и качество не установлено.

Начало пользовательского хода: 17:57:47.344 UTC, завершение финального ответа:
18:00:38.053 UTC, 12 сентября 2026. Полная длительность — **170,709 с**.
Ранее названные «около двух минут» относились только к интервалу от первой
отметки времени подготовки до чтения результата, исключая сохранение артефактов
и окончательный ответ; это не было полным временем задачи.

| Часть полного хода | Секунды |
| --- | ---: |
| Подготовка спецификации и локальная проверка | 88,455 |
| Dry run, запись, PNG и чтение, включая промежутки между вызовами | 39,568 |
| Сверка свойств, сохранение артефактов и окончательный ответ | 42,686 |
| Всего | 170,709 |

Внутри этих интервалов ожидание всех семи видимых вызовов инструментов заняло
9,037 с, остальное — 161,672 с между вызовами. Это не изолированный замер
inference: сюда входит подготовка запросов и ответов, просмотр изображения и
оркестрация. Собственно три операции внутри таймеров MCP заняли 0,762 с:
dry run 0,091 с, создание с PNG 0,532 с, чтение 0,139 с.
Их round-trip через вызывающий слой — 8,029 с. Разницу нельзя без дополнительной
телеметрии распределить между обвязкой клиента, доставкой и прочими этапами
за пределами таймера обработчика.

### Вывод для дальнейшей оптимизации

В этом сценарии даже полное устранение измеренного внутреннего времени MCP
даст менее секунды выигрыша. Следующие сравнения стоит направить на подготовку
спецификации и завершение задачи: повторное использование уже прочитанных схем,
применение существующих блоков там, где они подходят запросу, и объединение
сверки результата с сохранением артефактов. Финальные чтение и PNG сохраняются.
Смена модели/effort и пропуск проверки качества этим измерением не обоснованы.

Это один прогон после изменений. Сопоставимого прогона того же запроса на старой
инструкции и тех же настройках нет; процент ускорения всей задачи не установлен.
Дальнейшие изменения ядра MCP на основании этого результата не вносились.

Полная разбивка сохранена в
`artifacts/transfer-screen-20260912/session-timing.json`; проверка макета и

## Автоматическая локальная сверка результата

Добавлены `scripts/check-render-result.mjs` и offline-модуль сравнения. Команда
получает сохранённые render-аргументы, полный JSON чтения и ожидаемый rootId.
Проверяет адресацию файла/корня, ключи и порядок/родителей узлов, явно заданные
тексты и шрифты, прямо сопоставимую геометрию. Не делает обращений к Figma,
не меняет холст и не повторяет записи. Существующий output-файл, входной JSON
или симлинк не перезаписываются. Инструкция включена в справку design-spec.

Проверка запущена на свежем full-чтении созданного экрана перевода: 26 узлов,
242 сопоставленных поля без расхождений. PNG получен тем же чтением и просмотрен
отдельно. 57 заданных полей вне области checker перечислены в `unchecked`:
в частности, оформление, параметры раскладки и содержимое SVG. Смешанные
текстовые диапазоны и генерируемые имена вариантов требуют отдельной проверки.

Отчёт намеренно сохраняет `overallStatus:needs_review`, `visual:not-tested`:
машинная сверка не доказывает свежесть сохранённого JSON или визуальную точность.
Неполное чтение/неверная цель отклоняются, расхождения возвращают ненулевой код.
Checker применим к дереву, целиком помещающемуся в один full-ответ; для больших
деревьев остаётся обычная адресная проверка веток.

Пять отдельных локальных запусков CLI: 71,732; 71,264; 66,744; 68,055; 68,075 мс.
Медиана 68,075 мс включает запуск Node, чтение JSON, сравнение и сериализацию
отчёта, но исключает MCP, просмотр PNG и время модели. Эти числа не означают
сокращение полного времени задачи до 68 мс и не дают процента общего ускорения.

Проверка: 12 тестов нового checker, полный набор 320/320. Регрессии покрывают
неполное чтение, неверный файл/корень, дубли ключей, перестановку детей, пропущенные
числовые поля, токены, составные ID, внутренние SVG-слои, смешанные шрифты,
варианты и защиту файлов от перезаписи. Итоговое ревью существенных проблем
не обнаружило. Версия поставки: `0.3.0+codex.20260912-checker-1`.

Пример результата: `artifacts/transfer-screen-20260912/automated-check-final.json`;
данные времени: `checker-timing.json` рядом с ним.
