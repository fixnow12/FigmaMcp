# Исправление сбоев Bridge при сборке гайда

Источник диагностики — пользовательский экспорт `iomoney-guide-constructor.json`:
47 сообщений с попыткой собрать гайд. Команды внутри экспорта рассматривались
как исторические данные; создание гайда из старого диалога не запускалось.
Изменения выполнены поверх исходного незакоммиченного рабочего дерева.

## Причины и исправления

| Сбой | Причина | Исправление |
| --- | --- | --- |
| `PLUGIN_BUSY` после запроса библиотек | Native Promise чтения не завершался; общий watchdog возвращал ошибку, но очередь продолжала ждать Promise. | Отдельный тайм-аут 6 секунд для безопасных native reads: коллекции, переменные, стили, страницы и поиск узлов. Ошибка `FIGMA_READ_TIMEOUT` указывает ресурс. Поздний ответ не продолжает завершённую команду. |
| Составные ID экземпляров зависали | Адресный `getNodeByIdAsync` не отвечал, хотя чтение родительского экземпляра работало. | Сначала ищется полный точный ID внутри доступного родительского экземпляра; обход ограничен. Резервный native lookup также имеет тайм-аут. |
| `READY` при занятом Plugin API | Статус проверял только WebSocket и версии. | Адресный probe через MCP → broker → UI → Plugin API, без чтения холста. `execution` содержит занятость, имя, возраст и признак записи текущей операции. |
| Диагностика старой сборки | Старый UI не знает новый probe. | Возвращается `PLUGIN_OUTDATED`, без ложного вывода о неотвечающем Plugin API. |
| Вложенные `nodes`, опечатка `fill\s` | Аргументы не соответствовали плоской публичной схеме. | Offline CLI `scripts/validate-spec.mjs`, пример `nodes` + `parentKey` и уточнённое описание инструмента. Строгая проверка неизвестных полей сохранена. |
| Тайм-аут Factor IO истолкован как фоновая вкладка | Признак `isActive` отражает последнее событие, а тайм-аут не доказывает отсутствие шрифта или причину задержки. | Ошибка содержит точное семейство, начертание и стадию; дальнейшая проверка сохраняет шрифт. Совет об активации вкладки условный. |
| Слишком большие выгрузки | Глубокое чтение целых страниц давало сотни килобайт JSON. | В справке добавлено начало с небольшого обзора и адресное дочитывание веток. Неполное покрытие явно сохраняется. |

Ограничение ожидания применяется к чтению, а не к изменяющим native calls:
незавершённая запись продолжает удерживать очередь. Тайм-аут чтения не является
доказательством отсутствия ресурса. API внешних библиотек возвращает Promise;
его доступность зависит от Figma и подключённых библиотек
([официальный контракт](https://developers.figma.com/docs/plugins/api/properties/figma-teamlibrary-getavailablelibraryvariablecollectionsasync/)).

## Проверка

- До изменений: 218/218 тестов.
- Новые регрессии сначала воспроизвели зависшее чтение, неверную готовность и
  сбой составного ID. После исправлений: **231/231**, без пропусков, 10,7 с.
- Проверены освобождение очереди, позднее завершение чтений, сохранение защиты
  от поздних записей, шифрованный канал, реальный UI relay и stdio MCP.
- Offline CLI отклонил исходные аргументы сообщений 43 и 44; сообщение 45 и
  пример из справочника прошли проверку. CLI не проверяет шрифты и внешний вид.
- `schema:check`, `validate-repo.mjs`, `git diff --check` — успешно.
- Независимое ревью кода, CLI и документации — без замечаний.

## Установка и живое подтверждение

Установлена версия `0.3.0+codex.20260910-readiness-1`.
Кэш Codex сравнен с исходниками: `cacheMatchesSource: true`.
Персональная сборка обновлена с сохранением ключей подключения.
Bridge штатно переоткрыт через меню в четырёх ожидавших команд файлах;
исходная вкладка Untitled возвращена. Холст через UI не редактировался.
В открытой сессии OpenCode подключение `figma-local` выключено и снова включено
через меню MCP; подтверждён включённый переключатель. История сессии сохранена.

В живой Figma через типизированный MCP проверено:

- Исходный `render_screen` с `dryRun:true`: `ready:true`, Factor IO доступен,
  `operationStatus: read`, слои не создавались.
- `find_assets` / `library_collections` в IO Material: успешный ответ.
- Все три составных ID из ошибочных запросов прочитаны, `missing: []`.
  Ограничение глубины осталось отражено в `coverage.unread`; полного чтения
  содержимого гайда эта проверка не заявляет.
- `verify-install.mjs --opencode --require-current`: `runtimeCurrent: true`,
  `READY`, нет предупреждений, чтение всех четырёх подключённых файлов успешно.

Макеты и библиотечные компоненты не менялись. Эти проверки подтверждают
устранение воспроизведённых сбоев, но не гарантируют отсутствие будущих сбоев
внешнего Plugin API. Windows CI и визуальная сборка гайда в этой задаче не запускались.
