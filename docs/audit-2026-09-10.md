# Проверка и ускорение FigmaMcp — 10 сентября 2026

Проверено текущее рабочее дерево, включая ранее незакоммиченные изменения.
Исходные изменения сохранены. Макеты и библиотечные компоненты не редактировались.

## Исправления

| Область | Проблема | Исправление |
| --- | --- | --- |
| Пакетный поиск целей | Каждый `patch.key` заново обходил всю страницу. | Общий индекс для синхронного разрешения целей одного пакета. |
| Конфликты ключей | Кэш после ожидания шрифта мог пропустить внешний слой с таким же ключом. | Кэш используется только до первого ожидания; проверки перед добавлением слоёв остаются свежими. |
| Статус целевого файла | Устаревший плагин другого файла делал адресный `get_status` неготовым. | `fileKey` передаётся в диагностику; общий статус продолжает проверять все файлы. |
| Обслуживание broker | Ошибка чтения или PNG добавляла файл в неизвестные записи и удерживала обновление/завершение процесса. | Удержание применяется только к отправленным изменениям; неизвестные предыдущие записи сохраняются до успешного чтения. |
| Конкурентные переходы | Ручная правка во время асинхронной записи могла попасть в снимок отката или остаться незамеченной к концу пакета. | Сохраняется ожидаемое значение; проверяются результат каждого setter и весь пакет. Конфликт возвращает `partial`, внешняя правка сохраняется. |
| Проверка отката | Успешный Promise восстановления принимался за восстановленное состояние. | Добавлено чтение реакций после восстановления; конфликт отражается в `rollbackErrors`. |
| Представление реакций | Дублирующее поле `action` и порядок полей могли давать ложный конфликт отката. | Сравнение нормализует `action`/`actions` и порядок ключей объектов, сохраняя порядок действий и реакций. |

Поведение `action`/`actions` сверено с официальным [контрактом Reaction](https://developers.figma.com/docs/plugins/api/Reaction/).

## Скорость

Сравнение выполнено на поведенческой модели Figma: 2000 узлов, 100 правок
`opacity` по ключам, 2 прогревочных и 10 измеряемых прогонов для каждой версии
в одном процессе Node.js 22.23.2 на macOS. Исходный сгенерированный код сохранён
до изменения реализации.

| Метрика | До | После |
| --- | ---: | ---: |
| Обходы страницы на пакет | 100 | 1 |
| Время пакета, p50 | 21,4 мс | 0,85 мс |

Около 25× в этом тестовом сценарии. Это измерение обработки пакета на модели;
оно не измеряет сетевую задержку, загрузку шрифтов, рендеринг и полное время работы
реальной Figma. Добавление слоёв сохраняет свежие проверки конфликтов после ожиданий.

## Установка и работающий Bridge

Установлена сборка `0.3.0+codex.20260910-audit-1`. Сравнение кэша Codex с
исходниками подтвердило `cacheMatchesSource: true`. Персональная сборка Bridge
обновлена, `code.js` и ревизия UI проверены без вывода ключей подключения.

Живое чтение через MCP успешно выполнено для четырёх подключённых файлов.
После проверочных чтений broker автоматически обновился. Строгая проверка
`verify-install.mjs --opencode --require-current` завершилась успешно:
`runtimeCurrent: true`, `READY`, MCP/broker/plugin актуальны, предупреждений нет.
Та же строгая проверка из нового каталога кэша Codex также прошла: актуальные
версии и успешное чтение всех четырёх файлов подтверждены установленной копией.
Выделения пусты, поэтому PNG и реальные клики прототипа не проверялись.

У уже открытого чата может остаться прежний процесс MCP и каталог инструментов:
для загрузки новой установленной копии переподключите MCP или создайте новую задачу.

Остаётся архитектурное ограничение обновления между разными каталогами кэша:
broker отслеживает изменения собственного каталога. Если его прежний каталог
остался неизменным после установки другой версии, нужен разовый перезапуск по
README. Автоматическое принятие любой ревизии клиента не добавлено: старые и новые
AI-сессии иначе могли бы по очереди перезапускать общий процесс.
